# Pizza Boxer 02

Изолированный новый инструмент, скопированный из `grid_generator` 24 сентября 2026.
Все изменения продукта ведутся здесь. Общий фреймворк подключается из соседнего
`infra/framework`; оригинальный генератор и фреймворк не изменены.

## Запуск

Из родительской папки `js/YF`:

```sh
python3 grid_generator_02/tools/serve.py
```

Открыть <http://127.0.0.1:8766/grid_generator_02/>.
Сервер только раздает статические файлы; макет и 3D обрабатываются в браузере.

После изменения исходников, из `grid_generator_02`:

```sh
npm --prefix tools ci
npm --prefix tools run release
npm --prefix tools test
```

`release` собирает хешированные ресурсы и обновляет локальный `index.html`.
После сборки нужно перезагрузить страницу. Установка зависимостей нужна только
при первом запуске или изменении package-lock. Browser smoke:
<http://127.0.0.1:8766/grid_generator_02/tests/browser-smoke.html>.
Smoke использует отдельную IndexedDB `upgrade-pizza-boxer-02-browser-smoke-v1`;
рабочие черновики инструмента он не изменяет. Сервер отправляет Cache-Control: no-store.

## Что уже работает

- Существующий дефолтный пресет сразу открывается в 2D.
- 3D Preview собирает пятигранную крышку без дна из текущего макета.
- Камера: вращение, приближение, панорамирование, виды по граням и изнутри.
- Fold / Unfold и ползунок позволяют проследить складывание каждой боковины.
- Можно выбрать грань кликом на модели или кнопкой вида и перейти к ней в 2D.
- Размеры, видимость сторон, графика, текст и цвет обновляют превью.
- Печатное оформление снаружи; внутри — нейтральная непечатная поверхность.
- Локальная текстура ограничена 2048 px; шрифты встраиваются в промежуточный SVG.
- 3D загружается по запросу и рисуется при изменениях, без постоянного цикла кадров.
- Свой ID приложения, Symbol экземпляра и IndexedDB `upgrade-pizza-boxer-02-v1`.
  Миграция черновиков из прежних генераторов отключена.

Добавлен переключатель Construction:

- Lid — исходная пятигранная крышка.
- Box with base — шесть граней: крышка, дно и четыре стенки.
- Box with flap — семь граней: та же коробка с закрывающим клапаном.

У конструкций с дном три стенки соединены с дном, задняя стенка соединяет дно
и крышку. Отдельный ползунок Open lid открывает крышку, сохраняя положение
корпуса. Глубина клапана настраивается и ограничивается глубиной коробки.
Base и Flap доступны для текста, графики и собственной сетки; переход из 3D
открывает соответствующую грань в 2D. При смене конструкции верстка неиспользуемых
граней сохраняется. Конструкция входит в undo/redo и автосохранение.

Новые JSON экспортируются в формате 2.0: поле construction хранит тип и параметр
клапана, dimensions.depth явно обозначает глубину коробки. Пресеты 1.2 читаются
как пятигранные крышки. Размеры артборда SVG/PDF охватывают всю новую развертку.
Пути сгибов представлены иерархией панелей в PackagingModel и используются
для 2D, hit testing, экспортной геометрии и UV текстур 3D.

Панель Sides теперь открыта по умолчанию и содержит все грани, включая крышку.
У каждой грани видны название, физические размеры в мм и переключатель видимости.
Выбор синхронизирован между панелью, кликом по развертке и 3D. Locate приближает
выбранную грань в 2D или поворачивает к ней камеру в 3D. Слева вверху связаны
Dimensions и Grid — обе свернуты по умолчанию. Справа вверху связаны Sides
(раскрыта) и Objects (свернута). Каждая пара перемещается за любой заголовок;
сворачивание панелей независимо, длинное содержимое прокручивается внутри.
Главная сетка находится в Grid слева; собственная сетка и ориентация — в Sides.

Кнопка Add side предлагает доступное дополнение конструкции: сначала Base,
затем Flap. Те же действия доступны кнопками + у края развертки. Скрытые грани
можно восстановить через панель или кнопку на их месте в развертке. Добавление
дна также восстанавливает соединяющую заднюю стенку, если она была скрыта.
Верстка и собственные сетки сохраняются; каждое добавление — одно действие Undo.
Это добавление частей текущих конструкций 5/6/7, а не свободное моделирование
произвольной топологии. Импорт сложных дайкатов остается отдельным этапом.

Новые текст и графика создаются на выбранной стороне. Если она скрыта, добавление
объекта восстанавливает ее в той же операции Undo. Без выбранной стороны новый
объект попадает на главную грань. При запуске ничего не выделено; наведение и
добавление грани не включают обводку. Явный выбор в списке, на развертке или в 3D
включает выделение. Клик по пустому холсту в 2D/3D снимает его во всех видах;
перетаскивание холста и работа с настройками сохраняют выбор. Выбор, Locate
и камера не изменяют документ. Контуры выделения и кнопки не попадают в экспорт
или текстуру. Fit теперь действительно уменьшает развертку между панелями,
учитывает поворот холста; кнопки добавления сохраняют размер при масштабировании.

Коробки пока состоят из тонких плоскостей: компенсация толщины картона
и производственные клеевые клапаны относятся к следующим этапам.
Поле Depth — глубина крышки, а не толщина материала. PDF-экспорт унаследован
из текущего генератора; требования к редактируемым абзацам Illustrator еще
не реализованы. Импорт дайкатов намеренно не добавлен.

## Жесткие тубусы — 28 сентября 2026

В Dimensions → Construction доступны Rigid tube (одна обертка корпуса) и
Telescopic tube (корпус и отдельная цилиндрическая крышка). Construction
перенесен в начало панели; для тубусов размеры коробки заменяются параметрами
цилиндров. Крышку также можно добавить через Add Side или + Cap wrap на развертке.

- Body diameter — наружный диаметр корпуса; Body height и Cap height — высоты деталей.
- Overlap — глубина нахлеста; закрытая высота равна сумме высот минус нахлест.
- Wall thickness — общая толщина стенок обеих деталей; Radial clearance — зазор
  между наружной стенкой корпуса и внутренней стенкой крышки.
- Наружный диаметр крышки вычисляется как диаметр корпуса + 2 × (стенка + зазор).
  Поэтому ширины оберток отличаются: каждая равна π × своему наружному диаметру.
- Нахлест ограничен высотой деталей с учетом толщины круглого торца. При
  уменьшении деталей слишком большой нахлест автоматически уменьшается.
- Sides содержит Body wrap и Cap wrap. У крышки отдельная верстка, ориентация и
  собственная сетка. Круглые торцы видны только в 3D и не выбираются для верстки.
- Roll / Unroll сворачивает каждую обертку в цилиндр. Open cap сдвигает крышку
  вдоль оси, сохраняя корпус на месте. Inside открывает крышку и показывает сборку.
- В 2D зона Under cap показывает часть корпуса, перекрываемую закрытой крышкой.
  Этот ориентир и выделение не попадают в экспорт и текстуру.
- SVG содержит прямоугольные обертки в миллиметрах. Между ними технический
  промежуток 10 мм; круглых торцов в экспорте нет.
- Параметры, сетки и верстка сохраняются в JSON 2.0, Undo/Redo и локальном черновике.
  При возврате к коробке восстанавливаются ее прежние размеры; параметры тубуса
  и верстка крышки сохраняются для последующего возвращения.

Это модель двух телескопических деталей с общей толщиной стенки. Продольный шов
обертки фиксирован сзади и сходится встык: припуски на склейку, вылеты, профили
материала, внутренние муфты и проверка производственных допусков пока не добавлены.
Мягкие тубы остаются отдельным следующим семейством.

## Поворот сетки и верстки

Выберите поверхность в Sides или на развертке, затем задайте угол в существующем
поле Orientation: 0°, 90°, 180° или 270°. Поворот доступен и основной плоскости
коробки, и Body wrap тубуса. Корпус и Cap wrap поворачиваются независимо.

Поворачиваются сетка и все объекты выбранной поверхности; размеры развертки и
сама конструкция остаются прежними. При 90°/270° рабочие ширина и высота меняются
местами. Для основной поверхности параметры сетки пересчитываются согласно
выбранному Link Mode и блокировкам Grid; при связи с модулем это может изменить
размер модуля и связанную с ним типографику. На боковых поверхностях продолжает
работать прежняя логика общей или собственной сетки.

Ориентация одинакова в 2D, текстуре 3D и SVG; сохраняется в JSON, черновике и
Undo/Redo. Перетаскивание и изменение ширины объектов используют повернутые оси.
Кнопка Rotate canvas в верхней панели по-прежнему поворачивает только вид.

## Ссылки на макет

Кнопка с иконкой цепочки справа от пресетов копирует текущий документ, включая
несохраненные изменения. Используются кнопка и ShareCodec общего фреймворка.
Состояние сжимается в URL fragment: сервер и сервис коротких ссылок не нужны.
Открытие ссылки создает отдельный Shared-пресет и не стирает прежний черновик.

Сохраняются конструкция, размеры, повороты, сетки, текст, типографика, порядок и
видимость объектов, рамки/пропорции/режим кадрирования, имена файлов и Outline fonts.
Файлы пользовательских изображений (включая SVG) и шрифтов в ссылку не входят.
Стандартная графика восстанавливается по ссылкам на встроенный каталог версии 1.
Для отсутствующего файла видна рамка: выберите объект и нажмите Click to relink.

Для стандартного New проверена ссылка длиной 2029 символов. После 3600 символов
подсказка сообщает длину; жесткий бюджет приложения — 64 000 символов. Точность
и объекты ради длины не удаляются. При превышении предложен JSON. Это ограничение
приложения, а не гарантия приема такой длины любым мессенджером.
Ссылка использует текущий адрес инструмента; localhost доступен только локально.

## Растровые превью

Objects → Add Graphics принимает SVG, PNG, JPEG и WebP через существующее поле
загрузки и drag & drop. Растр декодируется локально и уменьшается до 1024 пикселей
по длинной стороне без увеличения маленьких изображений. Исходный файл не хранится.
Принимаются файлы до 20 МБ и изображения до 40 мегапикселей.

У изображения доступны обычные позиция, размер, поверхность, порядок слоев,
видимость, дублирование и Undo/Redo. Image frame задает исходные пропорции,
квадрат, 3:2, 4:3 или 16:9. Image fit вписывает все изображение либо обрезает его
по центру без искажения пропорций. Произвольное смещение области кадрирования
пока не добавлено.

Фото сохраняет цвет и кадрирование в 2D/3D; в SVG и текущем PDF вместо пикселей
экспортируется векторная рамка. JSON и локальный черновик содержат уменьшенное
превью. Замена/повторная привязка растрового файла сохраняет рамку и режим вписывания.

## Пользовательские текстовые стили

Внизу Text Styles выберите исходный стиль в Copy from и нажмите Add style.
Новый стиль получает собственное имя и независимые параметры. Он появляется
в панели такими же сворачиваемыми секциями, как четыре стандартных стиля,
и в списке Text style редактора текста. Duplicate копирует пользовательский стиль.

Доступны TT Commons Classic (Regular/Medium), Lunnen Display (100/200/300/400),
размер, интерлиньяж, трекинг и измерение по x-height. При импорте сохраняются и
промежуточные значения веса Lunnen Display в диапазоне 100–400. Размеры можно
вводить в mod или pt; внутреннее значение остается связанным с модулем сетки.
Изменения применяются ко всем объектам с этим стилем, включая боковые грани,
развертки тубусов, 3D и SVG. Файлы новых шрифтов пока не загружаются.

При удалении используемого стиля редактор предлагает выбрать замену. Удаление
и переназначение текста составляют одно действие Undo. Четыре исходных стиля
остаются на месте. Определения и ссылки на стили сохраняются в JSON 2.0,
локальном черновике и ссылке на пресет. Стиль не переносится в другой документ
самостоятельно. Поддерживается до 64 пользовательских стилей с уникальными именами.
Вход в числовое поле без изменения значения не округляет данные документа.

Сохранение именованных абзацных стилей в Illustrator через PDF по-прежнему
отдельная нерешенная задача; эта доработка расширяет стили самого редактора.

## Каталог технической маркировки

Objects → Add markings открывает каталог из семи знаков, выделенных из
существующих icons.svg и icons_kb.svg: EAC, Read instructions, Fragile,
Keep dry, PAP 21, PAP 20 и WEEE. Контуры сохранены; для каждого знака зафиксированы
версия, вариант, исходный файл и SHA-256. Исходные общие файлы не изменены.

Starting set предлагает прежний полный состав с PAP 21, состав из icons_kb.svg
с PAP 20, пару знаков обращения и Choose individual signs для выбора с нуля.
Можно включать знаки, менять порядок стрелками, задавать горизонтальную или
вертикальную компоновку и выравнивание вертикального столбца. Icon height задает
высоту каждого знака в модулях сетки выбранной стороны; Gap — долю этой высоты.
Включенные знаки имеют одинаковую видимую высоту без искажения пропорций.
Это сохраненные составы графики команды; подбор по нормативным требованиям
и утвержденные ограничения размеров/охранных полей пока не добавлены.

Предпросмотр показывает локальный черновик набора. Add markings или Apply changes
записывают одно действие в историю; Cancel оставляет документ прежним.
Набор — обычный графический объект: его можно двигать, дублировать, скрывать,
переносить на другую сторону и удалять. Edit markings снова открывает каталог.
Для свободного размещения каждого знака добавляйте их отдельными объектами.

Применение каталога задает размер через высоту знаков. Общую ширину/высоту набора
после этого можно менять обычными контролами графического объекта. При повторном
открытии каталога высота знака вычисляется из текущего размера набора, в том числе
если он был задан шириной. В 2D и SVG/PDF знаки остаются векторами;
3D получает их в текстуре макета.

JSON, Undo/Redo, черновик и ссылка сохраняют состав, выключенные позиции, порядок,
интервал и компоновку. Ссылка передает только рецепт и версии знаков; SVG
восстанавливается локально и не требует повторной привязки. Старый объект Icons
остается исходным SVG, пока дизайнер явно не нажмет Choose markings и Apply changes.
Отмена и Undo сохраняют или восстанавливают исходный SVG без перерисовки.
