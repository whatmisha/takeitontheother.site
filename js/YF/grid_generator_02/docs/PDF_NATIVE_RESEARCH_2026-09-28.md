# Нативные данные Illustrator: результат исследования

28 сентября 2026. Следующий этап после отрицательной пользовательской проверки
обычного PDF. **Нативный экспортер не реализован; редактируемость не подтверждена.**

## Что удалось проверить

Инспектор прочитал 9 имеющихся AI-файлов из проекта (8 различных нативных
содержимых) и оба контрольных PDF. Все исходники открывались только на чтение.
[Полный отчет без исходного текста макетов](../output/pdf/native-inspection.json)
содержит хеши файлов, версии контейнера, имена шрифтов/стилей, длины текстовых
диапазонов и признаки геометрии. В отчете нет шрифтовых файлов, PGF или копий макетов.

В AI-образцах Illustrator 29–30 обнаружены:

- PDF-контейнер, `/PieceInfo /Illustrator /Private`, потоки `AIPrivateDataN`.
  Один из файлов разбит на 12 последовательных блоков. При единственном блоке
  `/NumBlock` может отсутствовать. Сначала блоки собираются, затем распаковываются.
- Заголовок `%AI24_ZStandard_Data` длиной 20 байт и Zstandard. После распаковки —
  PostScript-подобное представление документа; оно **не выполняется** инспектором.
- Два ASCII85-блока: `AI11TextDocument` и `AI11UndoFreeTextDocument`.
  Второй действительно содержит текст в двух локальных образцах, поэтому его
  нельзя считать всегда пустым или безусловно игнорировать.
- Текст UTF-16, диапазоны абзацного/символьного оформления, таблицы шрифтов,
  таблицы именованных стилей, записи рамок и кеши глифов/раскладки.
- Ссылки `StoryIndex` / `FrameIndex` / `FreeUndo` из объектов рисунка в текстовый
  движок. Одного массива строк недостаточно для восстановления документа.

В таблицах проверенных образцов есть только стандартные `[Normal Character Style]`
и `[Normal Paragraph Style]`. Подтвержденного примера пользовательских стилей нет.
Рамки имеют одинаковый набор ключей `/99 /10 /0 /5 /6`, без четырех значений `/1`,
которые открытый парсер использует как размеры текстового слоя. Это **признак для
исследования**, не доказанная универсальная классификация point/area text.
Эталонной рамки с подтвержденной переверсткой среди прочитанных файлов не найдено.

В двух наших контрольных PDF Illustrator private data отсутствуют — ожидаемый
отрицательный контроль. Их PDF-теги не заменяют нативную модель Illustrator.

## Что это меняет в плане

Распаковать данные в браузере технически возможно: `fzstd@0.1.1` — чистый JS.
Он добавлен только в devDependencies исследовательских инструментов; редактор
и PDF-стенд его не загружают. Локальный инспектор использует Node и Python/pypdf
исключительно для исследования, **не как серверную часть продукта**.

Однако чтение существующего файла не доказывает возможность корректной записи.
Остаются неопределенными геометрия area text, ссылки на новые стили, валидность
кешей после изменения текста и поведение Illustrator при открытии самостоятельно
сформированного PGF. Копирование неизмененного private stream из шаблона не решит
экспорт произвольного макета. Замена только исходной строки при старых кешах
тоже не считается результатом.

Следующий содержательный эксперимент:

1. Получить один маленький PDF из Illustrator 30.8.1 с подтвержденными area text
   и именованными стилями, сохраненный с Preserve Illustrator Editing Capabilities.
2. Прочитать его этим инспектором и сопоставить текст, рамку, диапазоны оформления,
   связи с объектами и кеши. Пока значения числовых ATE-ключей — наблюдения,
   не опубликованная спецификация Adobe.
3. Подготовить браузерный пробный writer. Он должен менять текст на строку другой
   длины, размеры рамки и именованный стиль, согласованно обновляя PDF и PGF.
4. Проверить в Illustrator открытие одним действием, переверстку после изменения
   ширины, применение стиля к новому абзацу, кириллицу и дерево объектов.
5. Только после этого переносить механизм на модель редактора. При неудаче
   зафиксировать точную границу, не подменять требования сохранением внешнего вида.

## Минимальный эталон для следующего эксперимента

Один новый документ Illustrator 30.8.1, один артборд A4:

- Прямоугольная **Area Type** рамка 100 × 60 мм; создана перетаскиванием Type Tool.
- Два абзаца кириллицы/латиницы, достаточно длинных для автоматических переносов.
  Между ними обычный Enter, внутри первого — один Shift+Enter.
- Paragraph Style `Brand Body`: TT Commons Classic Regular, 12 pt, leading 16 pt;
  применить ко всей рамке.
- Character Style `Brand Emphasis`: TT Commons Classic Medium;
  применить к нескольким словам внутри второго абзаца.
- Сохранить PDF с включенным **Preserve Illustrator Editing Capabilities**.
  Закрыть и снова открыть: текст переверстывается при сужении рамки, оба стиля
  присутствуют в своих панелях. Этот один файл и станет эталоном.

Можно использовать нейтральный текст; содержимое реального макета не требуется.
Это разовый исследовательский образец, не новый шаг будущего пользовательского
экспорта. Целевой сценарий остается прежним: браузер → один PDF → Illustrator.

## Воспроизведение и проверки

```sh
python3 grid_generator_02/tools/inspect-illustrator-native.py sample.pdf --output grid_generator_02/tmp/native-report.json
python3 grid_generator_02/tests/illustrator-native-inspector.test.py
```

Нужны установленный pypdf и `npm ci` в tools. Инспектор запрещает совпадение
входного и выходного пути. Нет исполнения PostScript, записи в исходники или
вызова Illustrator. Неподдерживаемый/неполный контейнер возвращает ошибку,
а обычный PDF — явное отсутствие private data.

7 проверок: одноблочный поток без NumBlock, числовая последовательность 12 блоков
AIPDFPrivateData, пропуски/неоднозначность блоков, zlib и усеченный поток, обе
текстовые секции/разные окончания строк/UTF-16 с emoji, отсутствие private data
в обычном PDF, реальный Zstandard-образец. Во всех локальных примерах длины
имеющихся диапазонов оформления совпадают с длиной UTF-16-текста.

Ограничения инспектора: только наблюдавшийся словарный поднабор ATE, не универсальный
парсер PostScript/Illustrator; геометрический признак area text еще не подтвержден;
64 MiB лимит исследуемого файла и распакованных private data; зашифрованные PDF
не поддерживаются. Отчет не устанавливает редактируемость и не проверяет
производственную корректность макета.

## Первичные источники

- [Adobe: Optimize native and PDF file sizes](https://helpx.adobe.com/illustrator/kb/optimize-native-pdf-file-sizes.html):
  Preserve Illustrator Editing Capabilities добавляет PGF в PDF.
- [Open Design: illustrator-parser-pdfcpu](https://github.com/opendesigndev/illustrator-parser-pdfcpu/tree/225c40c9f5d0ea3ff0e793ee1dacc386c198c3d4):
  открытый читатель PDF/Illustrator; изучены `wasm/private_data.go`,
  `src/private-data/section-splitter.ts`, `text-document/section.ts`,
  `text-document/index.ts`, `text-document/layer.ts`. Готового writer в этом проекте нет.
  Это первичный код реализации стороннего читателя, не спецификация Adobe.
- [fzstd](https://github.com/101arrowz/fzstd): используемый Zstandard-декодер.

Числовые ключи, длины диапазонов и наличие секций дополнительно проверены
непосредственно на файлах репозитория; общая совместимость из них не выводится.
