# Browser PDF probe — 28 сентября 2026

Пользовательская проверка в Illustrator 30.8.1 **не пройдена**: текст оказался
в кривых, именованные стили отсутствуют, объекты вложены в группы с clipping mask. Подготовлен отдельный
браузерный стенд, который создает два контрольных PDF из исходного семантического
документа, минуя SVG. Рабочий Export PDF редактора по-прежнему использует прежний
экспорт с текстом в кривых. Стенд не читает рабочий макет, IndexedDB или пресеты.


[Исследование нативных данных Illustrator](PDF_NATIVE_RESEARCH_2026-09-28.md):
добавлен отдельный read-only инспектор PGF/текстового движка; исследованы
9 AI-образцов и 2 контрольных PDF. Нативный экспортер не реализован.
Следующий эксперимент требует эталона area text с именованными стилями,
сохраненного из Illustrator 30.8.1 с Preserve Illustrator Editing Capabilities.

## Открыть и воспроизвести

- [Стенд](http://localhost:8766/grid_generator_02/experiments/pdf/).
- [PDF с тегами абзацев](../output/pdf/pdf-probe-tagged.pdf).
- [PDF без тегов](../output/pdf/pdf-probe-plain.pdf).
- [Семантический контрольный документ](../output/pdf/source.json).
- [Результат независимой проверки](../output/pdf/inspection.json).

Каждый файл: две страницы A4, 20 исходных текстовых рамок, три встроенных шрифта.
Tagged-вариант содержит 30 элементов P, объединенных в 20 Div, координаты рамок,
классы оформления и ActualText с исходными абзацами. Plain-вариант содержит то же
рисование без логической структуры. Это сравнение влияния тегов на импорт.

Все байты файла создаются в браузере. Сервер раздает только статические файлы.
`experiments/pdf/runtime` — отдельная сборка PDFKit 0.20.2 + fontkit 2.0.4, около
536 KiB JS; основной редактор ее не загружает. Установленные пакеты остаются
в игнорируемом tools/node_modules. В рабочую сборку редактора PDFKit не включен.

```sh
npm --prefix grid_generator_02/tools run pdf:probe
npm --prefix grid_generator_02/tools run pdf:fixtures
python3 grid_generator_02/tools/inspect-pdf-probe.py
npm --prefix grid_generator_02/tools test
```

`pdf:fixtures` — только QA-утилита: использует **тот же собранный браузерный модуль**
для сохранения проверяемых артефактов на диске. Это не серверная функция продукта.
SHA-256 обоих файлов совпали с результатами кнопки в реальном браузере.
`pdf:probe:check` сверяет исходники и выходные JS по хешам. Для Python-инспектора
нужны pypdf, fontTools и PyMuPDF; генерация в браузере от них не зависит.

## Найденные ограничения и исправления

В fontkit 2.0.4 при встраивании выбранного веса переменного шрифта обнаружены:
несовместимый конструктор EncodeStream, потеря конечного счетчика повторяющихся
флагов точек, неполная Unicode-карта для заранее закешированного компонента.
Это давало исключение, поврежденные u.ss01/цифры tnum и пустую запись ToUnicode.
Для выбранного экземпляра также нужно превратить составные контуры в статические
и убрать инструкции хинтинга, относящиеся к прежней нумерации точек.

Совместимость исправляется узкими проверяемыми подстановками **во время сборки
стенда** в `tools/build-pdf-probe.mjs`; node_modules и исходные шрифты не меняются.
При изменении структуры библиотеки сборка должна остановиться для ревью патча.
Эти исправления еще не являются универсальной поддержкой произвольных шрифтов.

**Lunnen:** контуры соответствуют wght 400, но PDF сохраняет исходное PostScript-имя
`LunnenDisplayVariable-Thin`. Распознавание начертания и сохранение его при наборе
нового текста в Illustrator пока не проверены. Поддержка нескольких весов одного
переменного шрифта в одном PDF этим стендом не доказана.

Классы `Brand / Body` и `Brand / Medium` представлены в структуре PDF, но это
**не нативные Paragraph Styles / Character Styles Illustrator**. В файл не добавлен
PGF и не замаскирован JSON-пакет под данные Illustrator. Образец еще не экспортирует
произвольную развертку, цветовые профили или все объекты редактора; он проверяет
сначала самое рискованное требование — редактирование текста.

## Проверка в Illustrator 30.8.1 — отрицательный результат

28 сентября пользователь открыл контрольный файл и прислал скриншот в 13:55.
[Машиночитаемый протокол](../experiments/pdf/illustrator-review.json) хранится отдельно
от автоматических проверок и не перезаписывается при повторном анализе PDF.
Точный вариант файла (tagged/plain) и способ открытия пока уточняются; результат
нельзя автоматически распространить на оба файла и все режимы импорта.

| Критерий | Наблюдение пользователя |
| --- | --- |
| Редактируемый текст | Весь текст в кривых; на скриншоте Compound Path |
| Именованные стили | Отсутствуют |
| Структура объектов | Layer → Group → Clip Group → Clipping Path / Compound Path |
| Физические размеры | Правильные |
| Отображение символов | Визуально правильное; это не проверка кодировки при редактировании текста |
| Переносы | Визуально предположительно правильные |
| Переверстка абзаца | Не проверена; из кривых невозможно установить сохранение area text |

Повторная независимая проверка исходных PDF подтверждает живые текстовые операторы,
встроенные шрифты, ToUnicode и отсутствие W/W* и XObject. Поэтому кривые и
обтравочные группы появились после генерации. Какой этап открытия/обработки
в Illustrator это вызвал, пока неизвестно; не следует объявлять баг экспортера
или ошибку пользователя без уточнения.

Adobe различает открытие содержимого PDF и **Import PDF pages as links for optimal
performance** в диалоге открытия. По одному скриншоту нельзя определить настройку.
Пользователю задан один уточняющий вопрос о режиме открытия. Даже успешное сохранение
живого текста при другом режиме не докажет нативные абзацы или стили.

Следующий технический этап: отдельно проверить возможность браузерной записи
Illustrator-совместимых данных редактирования. PDF ClassMap / ActualText недостаточно
для объявления поддержки нативных стилей. Рабочий экспорт не заменяется этим
прототипом; вся функция PDF остается нерешенной в рамках исходных требований.

### Контрольный сценарий для последующих проверок

Доступа к управлению Illustrator в этой сессии нет. Для сравнения способа импорта:


1. File → Open → pdf-probe-tagged.pdf, Previewed Page (первая страница),
   Import PDF pages as links for optimal performance выключен. Установлены шрифты команды.
2. В блоке 01 выбрать текстовую рамку и изменить ее ширину. Должна происходить
   переверстка всего исходного блока, а не растягивание и не перемещение строк.
3. Добавить текст во второй непустой абзац; сохранить пустой абзац и ручной перенос.
4. В Paragraph Styles / Character Styles найти именованные стили Brand / Body,
   Brand / Medium и применить к новому тексту.
5. Проверить выбор шрифта Lunnen/веса 400, альтернативы, трекинг, кириллицу и NBSP.
6. На второй странице проверить повороты, размеры и Layers: лишние Clipping Groups.
7. Повторить для plain-варианта. Зафиксировать результат по каждому критерию.

Если текст распадается на строки или стили не появляются, полный пункт PDF остается
нерешенным. Следующее исследование — пригодный для браузера способ создания
Illustrator-совместимых данных редактирования; простая смена PDF-движка не считается
решением. До проверки рабочий экспорт не заменяется.
