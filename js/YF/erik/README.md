# Erik

Desktop perspective crawl in Lunnen Display. The font’s discretionary ligatures (`dlig`), including NN and the Lunnen wordmark, are always enabled for logo, crawl and text ending through the shared preview/export font loader. Open `erik/` through the YF HTTP server. No build or external services. The optional Lottie renderer is vendored locally and loads only for Lottie endings.

- Optional outlined logo, defaulting to two lines: Lunnen / Airis. It fills both frame dimensions with overflow cropped, recedes upright at the same constant world speed as the ribbon. It starts closer to the camera; both elements use the same perspective projection. Its fade is distance-based and automatically finishes before the crawl reaches it, with a 24 px clearance at 1080p. The normal fade window (5.5–8.5 seconds at speed 120) moves earlier when the actual glyph geometry requires it. The logo-to-text gap is a spatial offset along their shared motion path: entry time is gap ÷ speed. The default gap is 450 (first entry frame 00:03:23 at speed 120); a gap of 240 restores 00:02:00. Removing the logo starts the crawl immediately.
- The supplied 14 credit lines are the default body. Default Lunnen Blue is `#2353DB`, matching Pizza Boxer. Manual line breaks and paragraphs are supported.
- Font size (32–120, default 42), line spacing (0.8–3 × font size, default 1.5), weight, tracking and text measure are in the left Text style panel. Logo → text gap and Crawl → ending gap (both −2400…2400) are in the right Motion panel, below Speed, Tilt and Perspective. All-line justification is the default; Alignment is not exposed in the UI. Existing preset alignment values remain readable.
- The ribbon’s lower corners are pinned to the frame’s lower corners at every tilt, perspective and text measure.
- Tilt (default 70°), perspective (default 100) and one shared constant speed for logo and crawl (10–400); the outro starts once the final visible glyph has fully crossed the bottom edge. The whole ribbon then fades smoothly over 5–6 seconds, finishing on a whole-second duration. Full Credits at the confirmed settings is 00:23:00 (690 frames); its fade begins at 17.283 seconds, displayed as 00:17:09. Trailing blank lines do not extend the video. Motion remains at the selected constant speed during the fade.
- 1920 × 1080, 30 fps, no audio. MP4 uses H.264 with the chosen solid background. PNG frame and ZIP sequence always retain alpha.
- Play/pause (Space), Stop to return to frame zero, frame steps (arrows), exact frame scrubbing, MP4 (Cmd/Ctrl+E).
- Undo/redo outside text inputs and a local draft at `upgrade:erik:draft:v1`. Draft schema v8 stores the single text body and the active preset identity, preserves the gap setting, upgrades untouched v1 demo fields and corrects “graphical” to “graphic” in unchanged v2 default credits, while preserving authored fields.

## Implementation

`model.js` owns normalization, line wrapping, camera parameters, logo/crawl timeline and the frame plan. `renderer.js` uses the framework's font file, Canvas text shaping and mipmapped WebGL texture tiles. `render(settings, time)` is shared by preview and export. The renderer measures the rasterized logo and crawl ink once per layout, then analytically solves their projected separation to prepare the logo fade deadline. Gap, camera and typography edits invalidate this calculation; speed only retimes it. This also works with random seeking, leading blank lines and extreme logo proportions. If there is no safe lead-in, the logo is already hidden when the text enters. Preview is 1280 × 720; exported frames are 1920 × 1080.

`export-worker.js` renders exports off the UI thread. `exporter.js` owns worker lifetime, immediate cancellation and retry. `video.js` probes actual 1080p/30 H.264 support before encoding, applies encoder backpressure, and uses framework MP4 muxing. Sequence output uses the existing framework ZIP writer and zero-based padded filenames. Neither export changes the document or playback position.

Framework UI comes from the public barrel. `framework-export.js` is the documented worker adapter for the DOM-free `mp4Muxer` and `StoredZipWriter` modules; it avoids importing the UI dependency graph into a dedicated worker. Erik does not import another tool.

Browser requirements: WebGL, OffscreenCanvas, worker FontFace/FontFaceSet and Intl.Segmenter. MP4 additionally requires WebCodecs H.264 encoding, probed at runtime. When unavailable, PNG exports remain enabled. Serve over HTTPS or localhost.

Resource limits: title 200 characters, body 6000; text textures 192 MiB, compressed MP4 samples 256 MiB, ZIP 512 MiB. Limits show an error instead of producing an incomplete download.

## Presets and credits

One preset contains the entire composition: logo, a single body containing plain text and inline formatting, typography, colors, motion and the ending (including the original SVG/Lottie file). The native framework preset menu, `PresetSession`, `PresetStore`, history and dialogs own selection, saving, renaming, deletion and unsaved-change protection. Cmd/Ctrl+S saves; the standard ActionDock extras (J) provide Save as, Export JSON and Import JSON. Cmd/Ctrl+Shift+S saves a copy; Cmd/Ctrl+J exports JSON; Cmd/Ctrl+Shift+J imports it. The shared-link button includes all text and settings. `FileIntakeController` validates JSON files up to 12 MiB, including embedded ending assets before applying them. `document.js` writes v5 JSON and accepts v1/v2/v3/v4 files, converting their active editor to inline notation.

Presets live at `upgrade:erik:presets:v1`. The one-time additive migration retains both old storage namespaces, copies old projects intact, and fills old style-only presets with the current draft's content. Name collisions get a numeric suffix. A separate v7 recovery draft at `upgrade:erik:draft:v1` keeps unfinished edits and the selected preset across reloads. Playback position and UI panel placement are not part of the preset. The v3 notation migration backs up the original library under `upgrade:erik:presets:v1:before-inline-v3`, retaining inactive legacy text for recovery.

Shipped presets: **Lunnen Airis** (original credits) and **Lunnen Airis — Full Credits** (Lunnen team plus Photo production team). On first migration the extended preset inherits the current draft's settings. The repo copy uses the confirmed settings: 42 pt, 1.50 line spacing, speed 120, tilt 70°, perspective 100, logo gap 450, Lunnen Blue, and role/name layout. It contains 17 role/name pairs and two centered full-width headings, with blank-line separation between teams. Handles are preserved; Сергей Харченко is transliterated as Sergey Kharchenko. The original vocabulary (retouch, muah, dop backstage) is retained for consistency.

Content and Text style panels sit on the left; Motion sits on the right. The centered preview and floating timeline share the space between them. The timeline uses the framework panel surface, matching Grainy Land's drawing-tools palette, and separate circular panel-action icon buttons; its grip supports dragging. Side panels use shared collapse, drag and height-resize behavior.

The Crawl tab in Content uses one textarea, initially five lines tall. It can be resized vertically within the available Content panel height; excess text scrolls inside the field. The height limit updates when Logo is opened or resized and when the viewport or panel height changes. A line with `|` becomes independently aligned role/name columns: `art director | @enhanser`. A line enclosed in hyphens becomes a full-width centered heading: `-Lunnen team-`. Normal paragraphs, pairs and headings can coexist. Formatting markers are not rendered. Long cells wrap; the next pair begins below the taller cell. Column gap appears in Text style when the body contains pairs. Role/name alignment is no longer exposed in the UI; saved alignment settings remain readable for preset compatibility. The syntax hint lives in the ? help popup. The expand button beside Text opens a wide, non-wrapping textarea using the shared DialogHost. Apply preserves all line breaks and records one history transaction; Cancel/Escape leave the composition untouched.

The compact timeline has separate centered circular Play/Pause and Stop buttons, with the current segment on the left and editable MM:SS:FF timecode on the right in the same row. The range below retains tick marks for text entry, logo disappearance, crawl fade out and the optional ending. The caption reflects the current segment (Logo, Logo → Crawl, Crawl, Fade out, Gap → Ending, Ending, End). There are no separate marker buttons, frame-count label or loop control. These playback controls never alter export timing. `animations.js` defines the renderer/frame-plan interface for named animation types; the document currently supports `crawl`.

`npm run test:erik` covers full preset round trips, strict import validation, additive legacy migration, storage failure/retry, heading layout, column wrapping, draft recovery and timecode validation. `tests/library.html` exercises the real preset session and file intake with isolated temporary storage. `tests/browser.html` checks the full credits' raster against worker PNG, alongside MP4/ZIP exports and collision regression tests.

## Ending

Content → Ending offers None, Text, SVG and Lottie. Existing presets keep None. Text uses Lunnen Display, the current weight/tracking and text color, centered frontally without perspective; SVG and Lottie keep their original colors and proportions. Size fits the artwork into a percentage of the 1080p frame. The Content tabs use the standard segmented control and keyboard navigation; Motion contains five stacked sliders, including both gap controls.

The final card starts relative to the end of the crawl fade, shifted by `Crawl → ending gap / Speed`, rounded up to the next 30 fps frame. The default gap is zero, duration 3 seconds, size 60%, and both Fade in and Fade out are off. Each switch independently adds a smooth 0.5-second fade at its boundary, within the selected duration. With Fade out off the final frame stays visible. Old combined Fade settings migrate to both switches. Full Credits with a default ending becomes 26 seconds; a 450-unit gap at Speed 120 makes it 00:29:23. Empty/missing endings do not extend the crawl. An ending-only composition is supported; its gap is ignored when there is no preceding logo or crawl.

SVG, Lottie JSON and `.lottie` archives up to 5 MiB are accepted. SVG must be static and self-contained; embed images and outline fonts. External resources and active SVG content are rejected. Lottie uses the pinned MIT [dotLottie Web 0.81.0](https://github.com/LottieFiles/dotlottie-web), with its matching local WASM binary and no runtime CDN. It plays once at its source rate and holds the final source frame if the card lasts longer; shortening Duration trims the animation. Lottie features follow the runtime's support; outline fonts and embed assets for portable results.

`ending-model.js` owns normalized settings and frame timing. `ending-assets.js` validates imports and loads assets. `ending-renderer.js` composites a front-facing card over the common crawl surface. Lottie is paused and explicitly seeks to the requested local time in both preview and export. SVG is decoded once at output resolution in the document, then transferred as an ImageBitmap to the export worker; the original vector source stays in the preset. MP4, PNG sequence and current-frame PNG all use the same compositor. Asset errors disable export, and import validation preserves the previous composition.

`tests/ending.html` covers real text/SVG/Lottie/dotLottie rendering, exact preview/worker PNG equality, random seeking, transparent output, optional fades, gap timing, complete PNG sequence and actual H.264 decode. `tests/library.html` verifies that embedded assets save/restore through native presets and malformed embedded SVG cannot replace live content.

The shipped **Draft** preset uses the supplied Sparky Lottie, a 5-second ending at 36% size, gap −200 and Speed 150, with Fade in on and Fade out off. Revision 3 expands the Lunnen team to 12 credits and keeps a blank line before the Photo production team. Shipped Draft revisions refresh an installed Draft once; clean working copies follow the update, while unsaved edits, deleted presets and unrelated custom presets are retained. Large ending sources are stored once in the Erik IndexedDB database; local presets and the working draft hold internal references. Exported JSON and share payloads still embed the full original asset.

Both gap controls live in Motion and accept −2400…2400. A negative Logo → text gap starts with the crawl already advanced; automatic logo clearance still applies. A negative Crawl → ending gap brings the ending forward to overlap the crawl, clamped at frame zero. The total duration covers both animations, so an early ending does not cut off the crawl.

`tests/ligatures.html` checks NN and Lunnen case variants across weights/tracking, compares each text stage against unjoined glyphs, and verifies pixel-identical worker PNG output.
