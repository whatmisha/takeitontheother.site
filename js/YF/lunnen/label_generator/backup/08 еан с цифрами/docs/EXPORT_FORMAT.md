# Формат экспорта настроек

## Обзор

При нажатии на кнопку **Export Settings** создается JSON-файл с настройками макета. Файл организован так, чтобы его мог легко редактировать копирайтер или дизайнер без знания программирования.

## Структура файла

Файл организован по принципу **от простого к сложному**:

1. **Название пресета** — понятное имя макета
2. **Размеры** — ширина, высота, толщина
3. **Тексты** — все текстовые блоки (легко редактировать)
4. **Настройки сетки** — модуль, колонки, строки
5. **Цвета** — фон и другие цвета
6. **Типографика** — размеры шрифтов, интерлиньяж, трекинг
7. **Графика** — SVG-код в самом конце (не пугает копирайтера)

## Описание полей

### 1. Мета-информация

- **`presetName`** — автоматически генерируемое название с параметрами и датой
- **`version`** — версия формата файла (для обратной совместимости)
- **`timestamp`** — время создания в формате ISO 8601

### 2. Размеры (dimensions)

- **`width`** — ширина макета
- **`height`** — высота макета
- **`thickness`** — толщина (глубина боковых панелей)
- **`unit`** — единица измерения (всегда "mm")

### 3. Тексты (texts)

Массив текстовых блоков, каждый содержит:

- **`id`** — уникальный идентификатор (text_1, text_2, ...)
- **`content`** — текст блока (**ЛЕГКО РЕДАКТИРОВАТЬ**)
- **`style`** — стиль текста ("headline" или "text")
- **`position`** — позиция на сетке
  - `column` — номер колонки (1-12)
  - `row` — номер строки (1-19)
  - `baseline` — позиция на базовой сетке
- **`width`** — ширина блока в колонках

### 4. Настройки сетки (grid)

- **`module`** — размер модуля в мм (базовая единица сетки)
- **`margins`** — отступы от краев
- **`marginsUnit`** — единицы отступов ("mod" или "mm")
- **`columns`** — количество колонок
- **`rows`** — количество строк
- **`rowHeight`** — высота строки в модулях
- **`linkMode`** — режим связи параметров ("off", "rows-height", "module")
- **`visibility`** — что отображать на сетке

### 5. Цвета (colors)

- **`background`** — цвет фона в формате HEX (#dadde6)

### 6. Типографика (typography)

#### Headline (заголовки)
- **`size`** — размер в модулях
- **`lineHeight`** — интерлиньяж в модулях
- **`tracking`** — трекинг в em единицах
- **`useXHeight`** — использовать x-height для выравнивания
- **`fontWeight`** — начертание ("400", "500")

#### Text (основной текст)
Аналогичная структура для основного текста

### 7. Отображение (display)

Булевы значения для показа/скрытия элементов:
- **`dimensions`** — размерные линии
- **`labels`** — подписи
- **`sidePanels`** — боковые панели
- **`objects`** — объекты (тексты и графика)

### 8. Графика (graphics)

**⚠️ SVG-код размещен в конце, чтобы не мешать редактированию текстов**

#### blocks (массив графических блоков)
- **`id`** — идентификатор (graphic_1, graphic_2, ...)
- **`position`** — позиция на сетке
- **`height`** — высота в модулях
- **`svg`** — SVG-код графики

#### icons (блок иконок)
Аналогичная структура для блока иконок

#### claim (блок клейма)
Аналогичная структура для блока клейма

## Универсальность системы

### Автоматическое добавление новых параметров

Система построена так, что **новые параметры автоматически попадают в экспорт**:

1. Добавьте параметр в `Settings.js` (src/core/Settings.js)
2. Параметр автоматически сохранится через `settingsModule.getAll()`
3. В экспорте он появится в соответствующей секции

**Пример:** если добавить `borderRadius` в Settings:

```javascript
// В Settings.js
this.data = {
    // ... существующие параметры
    borderRadius: 5
};
```

При экспорте этот параметр автоматически попадет в секцию `settings`.

Для более понятной организации можно добавить его в `organizeSettingsForExport()` в нужную секцию (например, в `dimensions`).

### Обратная совместимость

Система поддерживает:
- **Старый формат** — плоская структура (для совместимости со старыми файлами)
- **Новый формат** — организованная структура (текущая версия)

При импорте старого файла он автоматически конвертируется.

## Как редактировать файл

### Для копирайтера

1. Откройте JSON-файл в любом текстовом редакторе
2. Найдите секцию `"texts"`
3. Измените содержимое полей `"content"` — это тексты на макете
4. Сохраните файл
5. Импортируйте обратно в приложение через **Import Settings**

**Пример редактирования:**

```json
"texts": [
  {
    "id": "text_1",
    "content": "Старый текст",  // ← Измените это на нужный текст
    "style": "headline",
    // ... остальное не трогайте
  }
]
```

### Для дизайнера

Можно редактировать любые параметры:
- Размеры (`dimensions`)
- Цвета (`colors`)
- Типографику (`typography`)
- Позиции текстов и графики

### ⚠️ Не рекомендуется редактировать

- `version` — версия формата
- `timestamp` — время создания
- SVG-код графики (если не уверены в синтаксисе)

## Техническая информация

### Где находится код

**Экспорт:**
- `src/svg/SVGExporter.js` → метод `exportSettings()`
- `src/svg/SVGExporter.js` → метод `organizeSettingsForExport()`

**Импорт:**
- `src/svg/SVGExporter.js` → метод `importSettings()`
- `src/svg/SVGExporter.js` → метод `normalizeImportedData()`
- `src/svg/SVGExporter.js` → метод `convertNewFormatToOld()`

**Настройки:**
- `src/core/Settings.js` → класс `Settings`
- Метод `getAll()` возвращает все параметры

### Процесс экспорта

```
1. Пользователь нажимает "Export Settings"
   ↓
2. script.js → exportSettings()
   - Собирает: settings, textBlocks, graphicsBlocks, icons, claim
   ↓
3. SVGExporter.exportSettings()
   ↓
4. organizeSettingsForExport()
   - Реорганизует данные в понятную структуру
   - Генерирует название пресета
   ↓
5. beautifyJSON()
   - Форматирует JSON с отступами
   ↓
6. Скачивается файл
```

### Процесс импорта

```
1. Пользователь выбирает JSON-файл
   ↓
2. SVGExporter.importSettings()
   ↓
3. normalizeImportedData()
   - Определяет формат (старый/новый)
   ↓
4. convertNewFormatToOld() (если новый формат)
   - Конвертирует в старую структуру
   ↓
5. script.js → importSettings()
   - Применяет все настройки
   - Восстанавливает тексты и графику
   ↓
6. Обновляет UI
```
