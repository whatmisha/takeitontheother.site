### 4. RenderQueue — батчинг обновлений

**Файл**: `src/utils/RenderQueue.js` (220 строк)

**Классы**:

#### RenderQueue
Объединяет множественные вызовы `updateGrid()` в один через RAF:

```javascript
class RenderQueue {
    // Запланировать обновление
    schedule(callback, params)
    
    // Выполнить все обновления
    flush()
    
    // Отменить
    cancel()
}
```

#### Debouncer
Отложенное выполнение (для пользовательского ввода):

```javascript
class Debouncer {
    constructor(delay = 300) // 300ms задержка
    schedule(callback)       // Запланировать
    flushSync(callback)      // Немедленно
}
```

#### Throttler
Ограничитель частоты выполнения:

```javascript
class Throttler {
    constructor(interval = 16) // ~60fps
    execute(callback)          // Выполнить
}
```

### 5. Интеграция в GridGenerator

**script.js**:

```javascript
// Инициализация
this.renderQueue = new RenderQueue();
this.renderDebouncer = new Debouncer(150);

// Новый метод для батчинга
scheduleGridUpdate(params = {}) {
    this.renderQueue.schedule(() => this.updateGrid(), params);
}
```

**Использование**:

```javascript
// ❌ Было (множественные вызовы)
input.addEventListener('input', () => {
    this.updateGrid(); // Вызывается при каждом символе!
});

// ✅ Стало (батчинг)
input.addEventListener('input', () => {
    this.scheduleGridUpdate(); // Выполнится один раз через RAF
});
```

## 💡 Технические детали

### Почему ZIP так быстро?

1. **Нет задержек**: Удалили `setTimeout(300ms)`
2. **Batch операции**: Все файлы обрабатываются сразу
3. **Один download**: Браузер скачивает 1 файл, не 100
4. **Сжатие DEFLATE**: Level 6 (~70% экономии)
5. **Async/await**: Параллельная обработка где возможно

### Почему батчинг работает?

1. **RAF синхронизация**: Обновления привязаны к кадрам монитора
2. **Объединение вызовов**: N вызовов → 1 рендер
3. **Отмена лишних**: Только последний запрос выполняется
4. **Стабильные 16ms**: Гарантированные 60fps
