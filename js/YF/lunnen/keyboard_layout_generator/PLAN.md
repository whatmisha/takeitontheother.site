# Keyboard Layout Generator — план реализации

## 1. Что и зачем мы делаем

### Философия инструмента

Это **редактор раскладок**, а не reproducer одного конкретного примера. Эталонные файлы (`examples/ground_14.svg`, `examples/ground_16.svg`) нужны только чтобы откалибровать дефолты и проверить точность — весь остальной интерфейс должен позволять создавать произвольные раскладки с нуля, с любым количеством клавиш и любыми ширинами.

Ключевое требование: **структура раскладки — это данные, не код**. Пользователь может изменить ширину любой клавиши, добавить/удалить ряд, заменить клавишу на другую, не прикасаясь к исходникам.

### Базируемся на `yf-ui-framework`

Фреймворк уже даёт нам готовые компоненты интерфейса:

- `Settings` — реактивное хранилище настроек (с сериализацией в JSON)
- `SliderController`, `PanelManager`, `ColorPicker`, `DragDropManager`, `DOMCache`
- `ZoomPanManager` — vector-zoom по `viewBox`, fit-to-screen, Cmd+0/1
- `HistoryManager` — undo/redo по снэпшотам
- `PresetManager` — подгрузка пресетов из `presets/manifest.json`
- `SVGExporter` — экспорт в SVG/PDF, JSON import/export, text-to-path

Мы НЕ трогаем интерфейсные шрифты фреймворка. Шрифты из `fonts/` (YSText-Regular и т. п.) используются только в *генерируемой* графике клавиатур.

### Ключевые входные параметры

- тип устройства и количество клавиш (лэптоп/внешняя, 14"/16", numpad опционально);
- размер базовой клавиши (ширина/высота), расстояния между клавишами, радиус скругления;
- **ширина любой отдельной клавиши** может быть переопределена (tab, caps, shift, enter, space, backspace и т. д.);
- «охранные поля» — внутренние отступы, за которые не должны выходить буквы и графика;
- размеры шрифтов для разных слоёв подписей;
- расстановка букв для нескольких языков (сейчас английский + русский).

Единицы измерения — **миллиметры** на всём пути: внутренние расчёты, отображение в UI, экспорт SVG.

## 2. Поэтапный план

План разбит на итерации. В конце каждой — работающий артефакт, который можно открыть в браузере и проверить визуально.

### Итерация 0 — скелет приложения (готово)

- `index.html` с тёмной темой фреймворка, левой зоной для канваса, правой панелью настроек.
- Точка входа `src/KeyboardLayoutApp.js`: инициализация `Settings`, `ZoomPanManager`, `SliderController`, `PresetManager`, `HistoryManager`, `SVGExporter`.
- На канвасе — пустой SVG с viewBox в mm, фоновая «подложка» (backdrop).
- На правой панели — базовые слайдеры геометрии и два цветовых пикера.

### Итерация 1 — равномерная сетка клавиш (готово)

- Рендер N×M прямоугольников с учётом базовой геометрии.
- Настройка radius, цветов backdrop и клавиш.
- Undo/redo, экспорт SVG с корректным размером в мм.

### Итерация 2 — декларативные раскладки (готово)

- `src/data/rowTemplates.js`: описываем ряды клавиш массивами объектов `{ id, kind, w, label, icon, chars }`.
- `src/layout/layoutEngine.js`: чистая функция `computeLayout(template, settings)` рассчитывает координаты для каждой клавиши.
- Переменные ширины (tab, caps, shift, enter, space, backspace), fn-ряд с отдельной высотой, дополнительная правая колонка (pause/insert/delete + стрелочный кластер).
- Пресет Laptop 14" повторяет геометрию `examples/ground_14.svg` с точностью ~0.01 мм.
- Экспорт SVG корректно сохраняет миллиметры (`width="…mm"` = размер подложки по раскладке + padding).

### Итерация 3 — редактируемая структура клавиш (готово)

Главная цель — превратить hardcoded-шаблон в живые данные и дать пользователю управлять структурой раскладки через UI.

#### Итерация 3a — инспектор клавиши (готово)

- **Template как данные.** `LAPTOP_14` / `LAPTOP_16` живут в `Settings.template` как mutable data. Шаблоны из `src/data/rowTemplates.js` — только *начальные заготовки* для пресетов.
- **Select-to-edit.** Клик по клавише на canvas подсвечивает её и открывает панель «Selected key» справа. Клик по пустой области — снять выделение.
- **Per-key inspector.** Поля: `id` (readonly), `label` (text), `kind` (dropdown), `Width mm` / `Height mm` — абсолютные override. Кнопка «Reset» убирает override.

#### Итерация 3b — CRUD клавиш и рядов + базовый label (готово)

- **Key actions:** Move left / Move right, Duplicate, Delete.
- **Row actions:** Move row up/down, Add row above/below, Delete row.
- **Базовый текст `label`** рендерится простым `<text>` по центру клавиши (без охранных полей и шрифтов из `fonts/` — это итерация 4).
- **Undo/redo** подключён ко всем правкам: структурным (CRUD), инспектору, слайдерам (с дебаунсом), цветам, чекбоксам и загрузке пресетов. Cmd+Z / Cmd+Shift+Z работают как ожидается.
- **Фикс:** selection-overlay помечен `data-interactive="true"`, так что SVGExporter вычищает его из экспорта.

### Итерация 4 — графика на клавишах

Разбита на три мини-шага, чтобы каждый был проверяемый на канвасе.

#### Итерация 4a — типографика (готово)

- `fonts/YSText-Regular.ttf` подключён через `@font-face` — работает и в браузере (canvas preview), и после экспорта (font-family в SVG).
- `renderKeyTypography` раскладывает символы по углам клавиши:
  - `char` без `shift` (буквы): `base` в левом верхнем углу, `ru` в правом нижнем.
  - `char` с `shift` (числовой ряд): 4 позиции — `shift`/`base` слева сверху/снизу, `ruShift`/`ru` справа.
  - `special` / `function`: `label` в левом нижнем углу.
- Отдельные слайдеры: `Char`, `Shift char`, `Label`, `Inner pad` (все в мм). Все под историей изменений.
- Позиционирование привязано к внутреннему прямоугольнику `padKeyMm` — этот же прямоугольник в 4c становится видимым «охранным полем».

#### Итерация 4b — библиотека иконок

- Вытащить иконки из `examples/ground_14.svg` (`tab_arrow`, `capslock_indicator`, `sound_mute`, `backspace_arrow`, ...) в `src/assets/icons.js` как карту `id -> { path, viewBox }`.
- Рендер иконки по `key.icon` поверх клавиши; позиция — над/рядом с `label` в зависимости от типа.
- Размер иконки — отдельный слайдер.

#### Итерация 4c — охранные поля (готово)

- Визуальный слой safeguard: тонкая обводка прямоугольника с отступом `padKeyMm` от края клавиши и радиусом, уменьшенным на тот же inset.
- Переключатель видимости в Visibility (Layers-панель) как третий toggle-chip рядом с Backdrop и Keys; выключен по умолчанию.
- Когда слой скрыт на канвасе — его нет и в экспорте, потому что это обычные `<rect>` без `data-interactive`.

### Итерация 5 — многоязычная раскладка

- Флаги `showLatin`, `showCyrillic` в Settings.
- Режимы позиционирования: только латиница, только кириллица, обе с разделением по четвертям клавиши (base-lat / shift-lat / base-cyr / shift-cyr).
- Независимые размеры шрифта и offsets для каждого алфавита.

### Итерация 6 — новые шаблоны-заготовки

- Laptop 16" (с numpad, меньше радиус скругления).
- External TKL (tenkeyless, без numpad, с полноразмерным ctrl/shift/enter).
- External Full (полная клавиатура с numpad).
- Каждый — preset JSON в `presets/`, загружающий готовую структуру. Сам `computeLayout` остаётся без изменений: шаблон пришёл как данные.

### Итерация 7 — production-ready экспорт

- Переключатель text -> path (встраивание шрифтов vs outlines через `TextToPath`).
- Слой охранных полей в экспорте (опциональный чекбокс, независимый от preview).
- Имена id'шек и слоёв идентичны нашим декларативным id (`space`, `ctrl_right`, `shift_left`), чтобы результат было удобно открыть в Illustrator.
- PDF A3 landscape с корректными полями.

### Итерация 8 — UX-полировка

- Inline-редактирование `label` прямо на canvas (double-click -> input).
- Drag-reorder клавиш внутри ряда, drag-reorder рядов.
- Snap-to-grid для нестандартных клавиш.
- Multi-select + bulk edit.
- Импорт/экспорт своих шаблонов в JSON.

## 3. Принципы разработки

- **Единицы.** Всё в мм. pt -> mm = `x 25.4/72`. Точность значений — 4-6 знаков после запятой там, где мы реплицируем эталонные размеры.
- **Data-driven.** Структура раскладки — это данные в Settings, а не код. Любые хардкоды — только для начальных заготовок.
- **Чистые функции.** `computeLayout` не трогает DOM. Рендер — отдельная функция, получающая результат layout engine.
- **Экспорт = источник истины.** То, что пользователь видит на канвасе, должно 1:1 попадать в экспортированный SVG. Любая визуальная подстройка делается через Settings, а не через ad-hoc CSS transforms.
- **No fake data.** Не захардкоживаем заглушечные значения. Все дефолты — из `examples/ground_14.svg`.
