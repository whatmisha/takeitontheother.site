# UIQ — итерация 2: завершение операции вместо ложного Done

Дата: 2026-09-21. Рабочие изменения, без commit/push этой итерации.
База предыдущей работы: `b614ffc795930c1b0322b88c26e27e575608a120`.
Все изменения этой итерации сделаны внутри `upgrade/`; оригиналы не редактировались.

## Сделано

- Wordplayer: PNG и SVG подключены к общему ExportFeedbackController; отсутствующая сцена — ошибка. Повторный клик во время работы присоединяется к текущему Promise. Ошибка больше не проходит через `aria-busy=false → Done`. Диалог ошибки сохранён; после неуспешной загрузки шрифта можно повторить запрос, rejected Promise не остаётся в font cache навсегда.
- Keyboarder: подключены SVG, PNG, PDF и скрытый JSON. Сохранены clean-export guard, восстановление выделения, форматы и параметры файлов. PDF `{ ok: false }` преобразуется в rejection; если собственный диалог уже сообщил ошибку, второго диалога нет. Отсутствующий результат PDF — ошибка, не успех.
- ApplicationShell: canvas PNG и SVG→PNG теперь ждут окончания `toBlob()` и запуска скачивания. Раньше Promise завершался сразу после постановки callback. Пустой Blob и ошибки декодирования/кодирования/скачивания отклоняют Promise; Blob URL освобождается при ошибке.
- Рендереры и расчёт геометрии не менялись. Сохранены Wordplayer scale=3/transparent и размеры общего PNG.
- HTML помечает explicit-кнопки до запуска приложения, поэтому старый capture-handler не выдаёт ложный Done во время инициализации. Добавлены невидимые `role=status` без изменения геометрии кнопок.
- Аудитор `uiq-3` показывает инвентаризацию владельцев feedback и записывает JS-точки входа в отчёт. Инвентаризация намеренно имеет статус «Проверить», а не «Совпадает»: наличие маркера не доказывает успешный экспорт.
