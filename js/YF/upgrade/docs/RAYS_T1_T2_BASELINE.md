# Rays Pattern: контрольная фиксация и изолированная копия

2026-09-22. Выполнены T.1/T.2 плана интеграции. **Это не завершённая миграция:** Rays имеет статус `migrating`, использует старый интерфейс и пока не подключён к общему UI host. На главной остаётся неактивное название. Следующий этап — T.3, отделение модели и renderer/exporter.

## Что создано

- `rays_pattern_generator/index.html`, `script.js`, `styles.css` — выбранная версия `lunnen/rays_pattern_generator/01`, без соседних архивов и без внешних runtime-зависимостей.
- `qa/migrations/rays/legacy-source.json` — точные UTF-8 строки исходных трёх файлов. Их bytes/SHA-256 проверяются по неизменённому `SOURCE_BASELINE.json`. Тесты не читают живой оригинал. Старые внешние URL внутри JSON — неисполняемая фиксация исходника, не подключения приложения.
- `harness.mjs` — весь исходный script исполняется в Node VM с явными заглушками DOM, Canvas, storage, image decode и скачивания. Функции не вырезаются регулярными выражениями и не переписываются для теста.
- `legacy.test.mjs` — контракт параметров/геометрии/артефакта и отдельно известные ошибки исходника.
- `geometry-fixtures.json` — семь фиксированных сценариев: default, classic rows, 3 rays/round/no dividers, gradient, wide gaps, scale 0.1 и scale 3. Каждый хранит последовательность действий, имя SVG, количества модулей/соединений/линий, первую/последнюю линию и SHA-256 нормализованной геометрии.
- `isolated-copy.test.mjs` — копия против замороженного оригинала и golden fixtures, независимость storage, статус каталога и отсутствие публичной ссылки.
- `COPY_MANIFEST.json` — исходные и первоначальные целевые hashes с перечнем разрешённых изменений. Это историческая точка T.2, не требование никогда больше не менять приложение.

`TOOL_CATALOG.json`, `qa/migrations/CONTRACTS.json`, выбор инструмента в UI-аудиторе и npm-команда обновлены. Новое приложение сразу входит в boundary check. Исторические manifests приёмки восьми существующих приложений не изменялись этой миграцией.

## Точные изменения относительно оригинала

1. Все три обращения к `rayPatternSettings` заменены на `upgrade:rays-pattern:settings:v1`. Нет fallback, автопереноса или очистки старого ключа.
2. Из CSS удалены две внешние CoFo font-face; UI использует `-apple-system, BlinkMacSystemFont, Inter, Segoe UI, Roboto, sans-serif`. Не загружаются CoFo/Arial из соседних папок или с сайта.
3. У страницы есть название migration preview, data favicon и явная маркировка старого UI со ссылкой на внутреннюю главную.
4. Нормализован завершающий перевод строки. Формулы, порядок примитивов, defaults, file IO и старые ошибки script **не менялись**. Это проверяется отдельным T.2 identity-test.

Оригиналы `lunnen`/`muted` только читались. Другие приложения и общие runtime-компоненты не изменялись в рамках Rays T.1/T.2. В общей рабочей папке могут одновременно находиться чужие изменения — не сбрасывать их и не включать автоматически в будущий commit.

## Контракт результата, который нельзя потерять

| Область | Зафиксированное поведение |
| --- | --- |
| Документ | 3000 × 1000. Scale изменяет геометрию, не viewport. Исходник не меняет модель при DPR/resize. |
| Количество лучей | Только 3, 4, 5, 6, 8, 10, 12, 14, 16, 18, 20, 24; при равном расстоянии snapping выбирает меньшее. |
| Смещение рядов | `Classic Mode` выключен → нечётные ряды смещены. Внутреннее имя `offsetRows` не соответствует прямой логике названия. |
| Default | 216 модулей, 210 соединений, 1290 линий. |
| Preview / SVG | Canvas рисует белыми линиями поверх серого CSS-фона; SVG — чёрные векторные линии на прозрачном фоне, без фонового rect/image/text. |
| Края листа | Примитивы за пределами листа сохраняются. Не вырезать их из массива ради «чистой» геометрии. |
| Структура SVG | Модуль — группа translate; соединения — отдельные линии. Нет viewBox/clipPath в legacy. Сохранять результат осознанно, не добавлять рамку preview в экспорт. |
| Gap / длина | При изменении gap сохраняется внешний радиус `totalLength`; при изменении длины этот радиус пересчитывается. |
| Gradient | Значение берётся по origin модуля; длина учитывает дополнительный коэффициент `rayLength / 56`. Соединения вычисляются отдельно. |
| Image | Взвешенная RGB-яркость, contrast относительно 0.5, invert, прежняя дискретная выборка; alpha исходник игнорирует. Без загруженных pixels используется ordinary geometry. |
| Filename | Обычное имя `ray_pattern_lw2.0_ll56_lc5_co19_sc1.0_hg20_vg10.svg`. Filename не является полным проектом и не содержит изображение. |

Все 12 ranges, их min/max/default/step проверяются отдельно. Для всех допустимых ray count, обеих полярностей Classic, caps/соединений и крайних Scale сравнивается Canvas/SVG. Нормализация для сравнения округляет координаты и толщину до 8 знаков, сохраняет linecap и порядок, отдельно проверяет цвет.

## Известные исходные ошибки — ещё не исправлены

1. Восстановление длины/gap не обновляет `totalLength`; последующее изменение gap скачком возвращает старый внешний радиус. Тест воспроизводит 45 вместо ожидаемых 90.
2. В image mode имя файла не записывает Highlights/Shadows, а восстановление localStorage игнорирует сохранённые tone values, если выключен gradient. Настройки теряются; сам источник изображения также не сохраняется.
3. Можно включить gradient, когда image уже включён: флаги оказываются одновременно true, приоритет имеет gradient. В новом UI нужны взаимоисключающие режимы.
4. Экспорт создаёт Object URL без revoke.
5. ⌘E не защищён от editable/composition/repeat; это обязан закрыть общий command routing.
6. Image picker не сбрасывает value, нет обработки ошибок reader/decode. Повторный файл и ошибка загрузки требуют отдельной проверки после FileIntake-интеграции.
7. При чётном количестве лучей вертикальный луч повторяется. Это влияет на число примитивов/геометрию; **не исправлять молча** при извлечении engine. До отдельного решения fixture сохраняет старое поведение.
8. Старый UI далёк от стандарта: фиксированные нижние строки могут перекрывать controls, другие отступы/слайдеры, нет общего dock/help/panels. Не накладывать поверх старых 800+ строк CSS новый слой исправляющих overrides; заменить оболочку на T.5.

Ошибки в legacy-тестах — описание отправной точки, не приёмочные требования к будущей исправленной версии. На T.4 создать отдельные ожидаемые результаты исправлений, не менять замороженный источник ради зелёного теста.

### Ограничения проверки

SVG в unit-тестах проходит настоящий legacy exporter/Blob builder, но скачивание перехватывает Node-заглушка; браузерные загрузки на диск не выполнялись. Image tests получают уже декодированные RGBA pixels, поэтому не проверяют настоящий chooser, декодер, масштабирование картинки браузером или повторный выбор файла. Browser pixel-diff, реальные экспорты, все размеры окна и полный lifecycle ещё впереди. Скрипты тестов и fixtures находятся внутри upgrade; исходники снаружи нужны только явной provenance-проверке.

Случайная `MutationObserver.observe(... not of type Node)` из INT-02 в этих двух свежих страницах не повторилась. Причина по-прежнему не доказана; один чистый запуск не закрывает общий console gate. Не заявлять исправление и не приписывать ошибку браузеру без stack/URL.

## Следующая ограниченная задача: Rays T.3

1. Проверить diff и запустить `test:rays-baseline`. Не перезаписывать параллельные изменения, не копировать оригинал повторно.
2. Извлечь чистые defaults/параметры и функции расчёта одного модуля, tone sampling и раскладки. Engine не читает DOM/localStorage/canvas; получает параметры, размеры и при необходимости pixels.
3. Сформировать один упорядоченный результат с модулями, лучами и соединениями. Его читают preview и SVG; не переписывать математику в двух renderer заново.
4. Сравнить новый результат с frozen legacy и всеми golden hashes, дополнительно с image/gradient и всеми допустимыми count. Сохранить odd-row polarity, clipping semantics, порядок и linecap.
5. Подключить модель к текущему adapter, пока оставив старый UI. T.2 identity-assert заменить адресной проверкой нового adapter, а frozen characterization tests оставить неизменными.
6. После чистой parity — T.4 исправления restore/file/URL, затем T.5/T.6 общий UI/команды через opt-in ToolUiController. Не расширять shared framework предметной математикой Rays.

Остальные семь новых инструментов остаются planned. До T.7 Rays не переводить в accepted и не включать ссылку на главной. Commit/push в этом этапе не выполнялись.
