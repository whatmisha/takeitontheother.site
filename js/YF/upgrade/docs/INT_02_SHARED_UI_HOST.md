# INT-02 — подключение нового инструмента к общему UI

Дата: 2026-09-22. Изменения только в `upgrade/**`, без commit/push. Состояние: **механизм реализован и проверен на native Canvas QA-стенде; console gate UI-аудитора остаётся открытым**. Ни одно из восьми новых приложений ещё не скопировано; их статус остаётся `planned`. Следующий предметный пакет — Rays T.1, не массовое копирование.

## Что готово

- Публичный `ToolUiController` из `framework/src/index.js`. Идентификатор, название, сводки панелей и действия передаются конфигурацией. Имена новых инструментов не добавляются в legacy-таблицы `UnifiedUiController`.
- Одно описание действия определяет подпись кнопки, комбинацию клавиш и строку в справке. `kind` явно различает `export`, `import`, `command`; `group` — `primary`, `extra`, `panel`. Generate и аудио-команды не получают статус экспорта из-за совпадения части ID.
- Основной экспорт: `mod+e`; JSON export/import: `mod+j` / `mod+shift+j`; дополнительные JSON-кнопки скрыты до J/О. `?` и `mod+backslash` принадлежат общему UI. Браузерные `mod+0/1` не регистрируются.
- Защита от повторных событий, ввода в поля/contenteditable, IME/composition, лишних модификаторов и открытого диалога. Буквенные команды используют физический код клавиши, включая русскую раскладку. `enabled()` проверяется также непосредственно перед действием, а не только при обновлении кнопки.
- Повторные жесты во время одной операции присоединяются к существующему Promise. Явный экспорт получает `Exporting…` → `Done` только после выполнения операции; exception/rejection или `{ok:false}` дают ошибку. После завершения разрешён немедленный повторный запуск, без блокировки на время анимации.
- Повторный `init()` идемпотентен. Новый экземпляр на том же документе уничтожает прежний UI. `destroy()` снимает listeners/timers/observer, посылает AbortSignal и не позволяет позднему завершению старой операции восстановить её UI.
- Источники и генерация остаются на панелях; экспорты, JSON и справка — в общем нижнем dock. Предпросмотр, алгоритм, кодирование/скачивание, file parsers и аудиоресурсы остаются собственностью приложения.

Прежние восемь инструментов **не переведены** на новый способ подключения: их совместимость сохранена. Это отдельная задача, а не скрытая часть INT-02.

## Как подключать

Сначала создать DOM и один экземпляр renderer/панелей/контролов через существующий публичный API. Подключить `othersite-styles.css`, собственную геометрию layout, затем `ui-contract.css`. Использовать общие классы (`select-input`, `text-input`, `pill-toggle-row`, `sr-only`, `panel-action` и др.), а не голые нативные элементы с новыми локальными skin-правилами.

```js
import { ToolUiController } from '../framework/src/index.js';

const ui = new ToolUiController({
    id: 'tool-id',
    title: 'Tool title',
    summaries: { shapePanel: () => `${settings.count} rays` },
    onError: error => showApplicationError(error),
    actions: [
        { id: 'regenerate', button: 'regenerateButton', label: 'Generate',
          kind: 'command', group: 'panel', shortcut: 'space',
          run: ({ signal }) => generate({ signal }) },
        { id: 'svg', button: 'svgButton', label: 'SVG',
          kind: 'export', group: 'primary', shortcut: 'mod+e',
          enabled: () => Boolean(model), run: () => exportSvg(model) }
    ]
}).init();
```

Правила для следующего исполнителя:

1. Для этих кнопок не подключать параллельно `actionDockAutoInit`, `unifiedUiAutoInit`, старые click listeners или вторую регистрацию тех же хоткеев в `ApplicationShell`. Новый UI контроллер — единственный владелец команд. Renderer и PanelManager создаются отдельно и не пересоздаются при одном лишь UI re-init.
2. `button` — ID существующей кнопки или её DOM-элемент; каждой команде нужна собственная кнопка. Primary/extra физически находятся в `.action-dock`, panel-команды — за его пределами. Разметка должна существовать к вызову `init()`.
3. `run` должен возвращать Promise **всей** операции, а не только запуска `toBlob`, worker или скачивания. Не проглатывать ошибки внутри экспортера. Если старый API возвращает `{ok:false}`, контроллер не объявляет успех. Сам UI не проверяет содержимое файла — artifact tests остаются обязательными.
4. При смене режима задать `enabled()` для недоступных в этом режиме команд и вызвать `ui.refresh()`. Скрытие панели само по себе не означает запрет хоткея: у свёрнутой панели рабочие команды должны оставаться доступными.
5. Обновлять state и связанные контролы согласованно. В fixture загрузка sample использует `app.sliders.setValue`, чтобы число, положение бегунка и рисунок изменялись вместе. Для полного импорта состояния использовать API конкретного приложения, не вызывать private `_syncControls` из нового UI host.
6. AbortSignal кооперативный: контроллер не может сам остановить чужой worker, микрофон или запись файла. Проверять сигнал и освобождать эти ресурсы в приложении. Отдельный `app.destroy()` не заменяется `ui.destroy()`.
7. Не переносить тестовые симуляции источников и JSON из fixture в production как готовые импортеры. Использовать `FileIntakeController` плюс собственный decoder/schema и предметные проверки.
8. Справка поддерживает текстовые labels, не HTML. `helpLabel` может отличаться от короткой подписи кнопки. Ошибки конфигурации (повторные ID/кнопки/хоткеи, неправильный kind/group, пустая комбинация, запрещённые команды) обнаруживаются до привязки.

## Дополнительно исправлено в общем baseline

### Свёрнутые сводки

На длинной строке обнаружен цикл: refresh записывал полную строку, затем сокращённую; MutationObserver снова вызывал refresh, который повторял обе записи. Первая тестовая вкладка перестала отвечать. Обновление теперь повторно измеряет текст только при изменении исходной сводки, доступной ширины или самого DOM-текста. Проверка 50 последовательных refresh подтверждает отсутствие новых записей после стабилизации; изменение ширины и значений всё ещё пересчитывает сводку. Ширина панели не увеличивается, лишние `mm` убираются перед CSS ellipsis.

### Lifecycle

`UnifiedUiController` ожидает готовый body и снимает отложенный DOMContentLoaded при destroy. Наблюдение использует общий `installDocumentObserver`; уничтоженный observer не соединяется повторно и не вызывает sync из уже поставленного callback. Добавлены тесты отсутствующего DOM, неудачного первого attachment/retry и callback после destroy.

Это воспроизводимые классы ошибок. Точная причина единичного сообщения `MutationObserver.observe: parameter 1 is not of type Node` из INT-00 без stack не установлена задним числом. Первый повторный прогон восьми iframe прошёл без этого сообщения, но при финальной перезагрузке аудитора оно появилось снова (10:25:11.220 UTC), без filename/stack. Все последующие восемь замеров завершились. В проверенном активном runtime единственный MutationObserver находится в общем helper и его observe защищён try/catch; остальные найденные observers — ResizeObserver. Этого недостаточно, чтобы объявить сообщение ошибкой браузерной автоматизации или конкретного приложения. Нужна отдельная привязка к источнику; дефект не закрыт.

Также устранён потенциальный цикл обновления справки при labels с кавычками/HTML entities: сравнивается исходное содержимое, а не отличающаяся сериализация innerHTML. Тест проверяет стабильность 50 повторных refresh и безопасное отображение `<SVG>` как текста.

### Статические проверки и CSS

- Pulsar использует отдельную версию auto-init `uiq-3`; checker сохраняет проверку наличия подключения, учитывая эту реальную версию.
- Pulsar v2 намеренно удалил `preambleLengthSlider` (подтверждено историей изменения codec). Проверяются семь конкретных оставшихся ranges и константы v2, а не просто уменьшается счётчик. Итог: 127 static ranges.
- Проверки Keyboarder/Wordplayer привязаны к действующим export modules/feedback operation, а не к старой форме строк в tool.js. Проверки clipboard Pulsar учитывают `button` вместо старой переменной `btn`, сохраняя проверку writeText и «Copied».
- В общем CSS `line-height: normal` для обратной навигации устраняет расхождение Wordplayer с Sparky.
- `framework:upstream:check` больше не читает соседний оригинал: все 50 сохранённых donor hashes проверяются внутри `upgrade`, как и working-status provenance. Отдельная `framework:source:check` явно проверяет оригинал, если он доступен. В этом окружении папка оригинального v3 отсутствует по прежнему пути; это не мешает локальной проверке. Исторические hashes/снимок не изменены. Новый тест запускает checker с Node filesystem permissions, разрешающими чтение только `upgrade`.
