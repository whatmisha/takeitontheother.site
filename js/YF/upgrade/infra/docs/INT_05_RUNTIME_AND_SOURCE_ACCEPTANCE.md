## Разделение ошибки окружения и ошибок приложения

В UI-аудитор добавлен ранний пассивный сбор `error`, resource error и `unhandledrejection`: сообщение, filename, строка, колонка и stack. Он подключается до runtime всех 16 приложений, но активен только с `?ui-audit` и на самом QA-стенде. Нет телеметрии, записи storage, перехвата console, подмены MutationObserver или подавления исключений. Отчёт показывает диагностику отдельно для аудитора, инструмента и двух эталонов. Пустой журнал не превращается автоматически в passed.

После исправлений выполнены 24 перехода по восьми новым инструментам с тремя загрузками аудитора. В ранних журналах всех четырёх документов — 0 событий ошибки. При этом журнал браузерного окружения зарегистрировал восемь сообщений `MutationObserver.observe: parameter 1 is not of type Node` без filename/stack (21:32:46.134–21:33:03.769 UTC).

Подготовлен независимый `infra/qa/ui-audit/observer-repro.html`: три пустых HTML iframe, только пассивный probe и обработчик кнопки навигации. Ни один загруженный скрипт не создаёт MutationObserver; нет framework, p5, генераторов или внешних ресурсов. Состав скриптов закреплён тестом.

- Первые 19 навигаций с маленькими видимыми iframe: без сообщения; длинный запуск остановлен таймаутом, 24 прохода здесь **не** заявляются.
- При геометрии аудитора (1440×900, два эталона скрыты за экраном) сообщение воспроизвелось пять раз: 21:37:05.536, 21:37:08.971, 21:37:15.395, 21:37:18.655, 21:37:25.065 UTC. В журналах самих документов — 0.
- Прозрачные эталоны в пределах окна также дали два сообщения на восьми переходах (21:38:48.094 и 21:38:54.503 UTC). Поэтому такая перестановка **не** внесена как исправление в настоящий аудитор.

**Вывод по исключению зависимостей:** эта ошибка воспроизводится независимо от кода инструментов и общего фреймворка, в браузерном окружении встроенных окон. Конкретный внешний скрипт/строка по доступному журналу не установлены; сам внешний дефект не исправлен. Минимальный стенд теперь позволяет проверять его отдельно. Нельзя подменять этот вывод обещанием, что ошибок выполнения вообще нет.

**Уточнение плана приёмки:** данная воспроизведённая вне приложений сигнатура больше не блокирует автоматически приёмку каждого генератора. Другие исключения, ошибки из раннего журнала приложения, зависания или невыполненные предметные сценарии по-прежнему блокируют соответствующий инструмент. Ни одного сообщения не фильтруем и не скрываем. Это не основание принять остальные шесть без их проверок.

## Исправления источников

1. Rays и Random Lines: удалён `src="#"` у пустых превью — браузер пытался декодировать HTML текущей страницы как картинку.
2. Общий FileIntake: прерывание загрузки при pagehide возвращает прежние state/status, сохраняет прежний источник и доступность Remove. Для первого файла возвращает пустое состояние, а не вечное Loading.
3. Новый `FileIntakeController.reset()` синхронизирует UI после сброса модели владельцем, отменяет позднее завершение операции и не размножает обработчики. Не вызывает частный onRemove самостоятельно.
4. Rays Reset использует этот reset: preview src отсутствует, статус пуст, Remove скрыт, input очищен. Результат проверен в живом браузере.

Тесты двух дефектов FileIntake сначала воспроизвели сбой, после изменения прошли. Rays callback отдельно проверен на read error, decode error и позднее декодирование после ухода/возврата документа. Проверки lifecycle с эмуляцией `persisted` не выдаются за реальный BFCache во всех браузерах.

## Asterisk — приёмка текущего объёма переноса

- Реальные preview/export функции проверены на 128 комбинациях: оба режима, layers 0/1/2/7, восемь scale и оба caps. Исправлено только лишнее нулевое повторение в axes SVG; частная геометрия сохранена.
- Браузер: layers=7, tessellation, scale=1:128, round caps, Show grid=false; затем axes, scale=1:1, butt caps, Show grid=true. Оба SVG скачаны, валидны, конечны, 1920×1080; один dock, без overflow/ошибок приложения.
- Артефакты: `pattern (2).svg` — 570 paths, scale 0.0078125; `pattern (3).svg` — 129 paths, scale 1. Метаданные в `INT_05_EXPORT_EVIDENCE.json`.
- **Сетка не удалена из экспортного формата.** Как закреплено исходным планом, дублированная grid присутствует в SVG и при отключении её отображения. Show grid не переосмыслен как Include grid. Для такого изменения нужно отдельное решение; текущая приёмка подтверждает сохранение формата, а не WYSIWYG сетки.
- Максимум 100 слоёв не прогонялся и не объявляется безопасным; выполнен именно ограниченный стресс, предусмотренный планом.
