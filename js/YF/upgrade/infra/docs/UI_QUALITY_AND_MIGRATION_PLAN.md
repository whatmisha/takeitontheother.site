## 2. Быстрый рабочий процесс для пользователя

Открыть `http://127.0.0.1:8010/upgrade/qa/ui-audit/`.

1. Выбрать инструмент и размер окна, нажать «Открыть и проверить».
2. Посмотреть отклонения: элемент, свойство, фактическое значение, эталонное значение.
3. В «Рабочем окне» открыть нужную панель или режим, затем нажать «Повторить замер». Скрытые элементы не получают фиктивный статус «проверено».
4. Описать шаги и ожидаемое поведение в поле наблюдений. Скачать отчёт `.md`; при визуальной проблеме добавить скриншот нужного состояния.
5. Передать отчёт следующей задаче: «Исправить только указанный компонент; проверить его во всех потребителях; не менять генерацию».

Аудитор не нажимает кнопки экспорта и не записывает настройки сам. Однако встроенные приложения остаются настоящими приложениями: они запускают свой код и используют обычное хранилище этого origin. Это не изолированный профиль браузера. Перед экспериментами со своими данными сохранить проект. Для автоматических прогонов потребуется отдельный чистый browser context с тестовыми настройками.

### Возможности и ограничения первой версии

Проверяются вычисленные браузером стили навигации, основных кнопок, справки, заголовков групп, подписей и геометрии обычных range; центрирование и нижний отступ ActionDock; запрещённые UI-шрифты и веса; наличие написанных на кнопках шоткатов в справке. Эталоны кнопок Sparky и заголовков Wordplayer дополнительно сверяются с закреплёнными значениями.

Снимок цветов делается после ожидания завершения переходов; активные, disabled, hover/focus и feedback-состояния не выдаются за normal. Ожидание ограничено: незавершённая операция не должна блокировать аудит.

Это диагностический инструмент, не полная автоматическая приёмка. Он пока не проверяет все псевдоэлементы range, фактически использованный системный шрифт, цветовые градиенты, dropdown во всех состояниях, работу команд, результат экспорта, undo/redo и мобильный Sparky. «Совпадает» относится только к перечисленным свойствам текущего состояния. Например, `line-height: normal` и `16px` могут дать похожий результат; такое отличие требует решения, а не бездумного CSS-патча.

При перезагрузке самой страницы аудитора в браузерных логах наблюдалась ошибка `MutationObserver.observe: parameter 1 is not of type Node`; источник/stack браузер не предоставил. В отдельно открытых Wander Bender, Wordplayer, Sparky и Dither error-логи были пусты. Измерения и повторное открытие встроенных инструментов завершились, но это не основание объявлять весь прогон «0 console errors». Для этапа C нужно локализовать ошибку именно при reload iframe-стенда, отдельно от подтверждённых дефектов приложений, и включить сбор ошибок в runner. Сам текущий аудитор консоль не отслеживает.

## 3. Подтверждённые проблемы и риски

| ID | Находка | Основание | Следующее действие |
| --- | --- | --- | --- |
| UIQ-01 | SHAPE / DISTRIBUTION в Wander Bender отличаются от LIGHT PIXELS | В браузере 14.4px / 500, padding-top 20px, margin-bottom 8px; у Wordplayer 12px / 400, 12px и 24px | Один общий компонент заголовка группы; исправить конфликт специфичности, а не добавить ещё один локальный `!important` |
| UIQ-02 | Пять основных кнопок экспорта белые | Pizza Boxer, Sticky Fingers, Dither, Wander Bender, Pulsar Coder: `rgb(255,255,255)` против Sparky `rgb(210,210,210)` в normal | Найти владельца цвета и исправить общий вариант primary со всеми состояниями |
| UIQ-03 | Нижняя панель Dither визуально и семантически перегружена | В одной цепочке Image / remove / Layout / remove / PNG / Transparent / scale; одинаковый стиль не объясняет отношения | Сгруппировать источники отдельно от результата, но оставить всё внутри общей нижней центрированной группы |
| UIQ-04 | В Dither на кнопке есть ⌘I, а в общей справке его нет | Браузерный отчёт и частный keydown-handler Dither | Справка и клавиатура должны строиться из одного реестра действий |
| UIQ-05 | Общий feedback путает disabled и выполняющийся экспорт, а click — с успехом | `UnifiedUiController.syncExportStates()` считает disabled признаком working; `handleClick()` вызывает success, не ожидая результат; при старте Dither наблюдалось Done без пользовательского экспорта | Явный жизненный цикл операции, отдельный от доступности кнопки |
| UIQ-06 | Разные системы могут владеть одним шоткатом | В Dither есть частные e/o/i-handlers, рядом общие контроллеры | Проверить количество вызовов на один keydown; риск двойного исполнения, а не доказанный двойной экспорт |
| UIQ-07 | Component Lab не представляет финальный CSS приложений | `framework/component-lab/index.html` не подключает `framework/css/ui-contract.css` | Свести лабораторию к тем же стилям и компонентам, что реально используются в инструментах |
| UIQ-08 | Исторический отчёт называется свежей live-проверкой | `scripts/check-final-live-acceptance.mjs` читает `FINAL_LIVE_ACCEPTANCE.json` и проверяет поля/существование файлов, без запуска браузера | Отделить проверку исторических свидетельств от свежего браузерного прогона |
| UIQ-09 | Незначительное отличие навигации Wordplayer | Вычисленный line-height 16px вместо normal у Sparky | Сверить геометрию текста и закрепить осознанное решение; не считать поломкой только по строке CSS |
| UIQ-10 | Документация переносимого пакета отстаёт от версии | `extracted/ui-garage/VERSION.json`: 1.0.2; `docs/UI_GARAGE_EXTRACTION_STATUS.md`: 1.0.0 | При следующем релизе разделить историческую приёмку 1.0.0 и текущую версию |

Причина UIQ-01: в `framework/css/ui-contract.css` селектор `.controls-panel .control-section > h3` специфичнее `.controls-panel .control-field-heading`; оба используют `!important`. Поэтому общий вид обычного h3 перебивает специальный групповой заголовок. В Wordplayer остаётся другой локальный `.tone-group-heading`. Само присутствие общего CSS-файла не означает единого компонента.

Причина систематического пропуска: статические проверки нужны для границ и подключения, но поиск названия класса не проверяет итог каскада. Кроме того, некоторые различия уже записаны в тесты как частная специфика — например, размер thumb Dither в `check-range-contracts.mjs`. Для каждого такого исключения нужно заново решить, действительно ли оно нужно функции инструмента или просто наследует старое оформление.

## 4. Правила, которые становятся проверяемым контрактом

### Общее для всех инструментов

- UI-стек `-apple-system, BlinkMacSystemFont, Inter, Segoe UI, Roboto, sans-serif`; только 400 и 500; никаких Arial / TT Commons / CoFo в UI. Шрифты генерируемой графики не затрагиваются.
- Типографика, высоты, радиусы, отступы, цвета и состояния семейств контролов: button, pill/checkbox, select, numeric field, ordinary range, colour range, group heading, panel header, summary, dock, help.
- Основные кнопки и нижняя группа — по Sparky. В normal основная кнопка 16px / 500 / 36px / `#d2d2d2`; hover/focus/disabled/working/success/error описываются отдельно, без угадывания по normal.
- Групповые заголовки — по Wordplayer. Сначала перенести реальную проверенную разметку и геометрию, включая разделитель и поведение первой/последней группы, затем заменить два локальных варианта.
- Collapse не меняет ширину; сводка сначала сокращается по смыслу, затем получает ellipsis; последний блок панели не создаёт удвоенный нижний отступ.
- `?` показывает актуальные команды; `⌘/Ctrl+E` — основной экспорт, `⌘/Ctrl+J` — JSON export, `⇧⌘/Ctrl+J` — JSON import, `J/О` — extras, `⌘/Ctrl+\` — collapse/restore. Не возвращать конфликтующие с браузером ⌘0/⌘1.
- Клавиатура учитывает раскладку, repeat, модификаторы, editable-target и открытые диалоги. Один пользовательский жест — один вызов действия.
- Export feedback отражает результат операции; недоступный экспорт не означает загрузку. Для быстрых операций мягкое короткое подтверждение, не блокирующее повторный клик.

### Что остаётся частным

Математика и renderer, единицы и диапазоны, формат и содержимое файлов, специфические параметры, image/raster algorithms, Google Sheets, приоритетные мобильные сценарии Sparky. Разные значения и наличие контролов — нормально; разные стили одного семейства без причины — нет.

Особый range может иметь две ручки или доменную шкалу, но это не разрешение на случайный другой шрифт и вертикальный ритм. Colour range должен оставаться цветовым и обновлять градиент; обычный range не должен получать его CSS. Исключения фиксируются адресно: инструмент, компонент, свойство, причина, состояния и проверка. Нельзя разрешать исключение сразу для всех стилей приложения.

## 5. Порядок работ и условия завершения

Не исправлять восемь интерфейсов восемью независимыми CSS-патчами. Единица работы — одно семейство компонентов или одна общая операция, затем проверка всех его потребителей. Каждый пункт ниже — отдельная ограниченная задача; commit только после проверки.

### A. Зафиксировать эталоны и исправить заголовки — следующий шаг

1. Снять эталонные normal/first/last/collapsed состояния Wordplayer и контрпример Wander Bender.
2. Выделить общий групповой заголовок и группу с явным владением отступами: контейнер отвечает за промежутки, последний ребёнок не добавляет лишний внешний отступ.
3. Подключить Wordplayer и Wander к одному компоненту, удалить перекрывающие локальные правила только после проверки. Не расширять глобальные `h3`, `label`, `input` селекторы.
4. Перепроверить все восемь инструментов; pixel/header изменения не должны менять значения, события или renderer.
5. Дополнить тест реальным computed-style + screenshot сценария; приложить замер до/после. Проверить переполнение панели и размер после collapse.

Готово: одни правила, совпадающие измерения и утверждённый вид обеих страниц; статический поиск класса не заменяет эти условия.

### B. Общая нижняя панель и честный экспорт

1. Исправить primary/secondary/icon/pill-варианты: normal, hover, focus-visible, disabled; без обводки у экспортных кнопок. Проверить пять выявленных белых кнопок.
2. Описать действия как данные: `id`, `label`, `shortcut`, `run`, `enabled`, `group`, `options`. Один источник создаёт кнопку, шоткат и строку справки. Частный адаптер предоставляет операцию, общий framework — оформление и взаимодействие.
3. Заменить эвристику disabled/click на `idle → working → success|error → idle`. `enabled=false` — самостоятельное состояние. Синхронный результат нормализуется через Promise; rejection никогда не превращается в Done. Повторный экспорт и восстановление подписи покрыть тестами.
4. Для Dither (обновлено по замечанию пользователя): источники Image / Layout и привязанные remove находятся на панели Texture, в отдельной группе Sources. В центрированном dock только ? и выход PNG / Transparent / scale. ⌘O/⌘I работают и при свёрнутой панели. Не удалять alpha, масштаб и второй импорт ради похожести на Sparky.
5. Проверить 1440, 1280, 1024px: центр, нижний отступ, wrapping, отсутствие обрезанных действий. Для Sparky дополнительно 390/430px. Не объявлять остальные инструменты mobile-ready.
6. На каждом инструменте сравнить клик и хоткей; успешный, недоступный, быстрый, долгий, ошибочный экспорт; повторный запуск; содержимое скачанного файла.

Готово: общий внешний вид и жизненный цикл при сохранении частного набора действий; справка не расходится с реальными командами.

### C. Укрепить контроль качества, чтобы пользователь не был единственным тестером

1. Обновить **существующий** Component Lab: те же imports, CSS-порядок и компоненты, что в приложениях. Не создавать третий каталог копий с идеальными стилями, которые нигде не используются.
2. Ввести машинный список ролей и тестовых сценариев, не размножая хрупкие селекторы по тестам. Текущий аудитор использует legacy IDs как переходный мост; постепенно перейти на роли компонентов.
3. Компонентные сценарии: normal, hover, focus-visible, active/selected, disabled, loading, success/error, open/closed, collapsed, длинный текст, reduced-motion. Дополнительно range min/max, HSB hue-change, toggle wrapping, fixed/auto.
4. Интеграционные сценарии восьми приложений: начальное состояние, каждый режим, закрытые/открытые панели, dynamic text block, edit mode, image loaded/empty/invalid, JSON extras, восстановление проекта. Сохранять точные шаги воспроизведения.
5. Сделать автоматический браузерный runner: отдельный профиль, фиксированные viewport/browser/assets/fonts, стабильные данные/seed там, где нужен renderer. Снимать реальные computed styles, геометрию и скриншоты; DOM-сравнения дополняют, а не заменяют визуальные.
6. Не сравнивать случайно сгенерированную графику pixel-by-pixel без фикстуры. Для UI снимать панели отдельно; для генерации сравнивать геометрию/артефакты на фиксированном входе. Антиалиасинг не должен маскировать пропавшие кнопки.
7. Новый отчёт обязан содержать commit, dirty-статус или hash файлов, время, браузер, viewport, сценарий, данные/seed, CSS и ссылку на evidence. Старый JSON можно проверять на целостность, но нельзя печатать его счётчики как свежий live-run.
8. Внести адресные исключения с обоснованием и проверкой. Baseline обновляется только после просмотра diff человеком; массовая перезапись baseline не является исправлением.

Практический минимум для каждого небольшого фикса: targeted unit-тест, текущий UI-аудитор, браузерное состояние проблемы и smoke остальных потребителей. Перед выпуском — вся матрица восьми приложений, экспортные артефакты, desktop и Sparky mobile.

### D. Последовательный проход по оставшимся семействам

После A/B: вертикальные стопки контролов → toggles/choices → numeric fields и единицы → dropdown/preset меню → color picker → dynamic panels → import/help/shortcuts. Для каждого семейства проверять и внешний вид, и поведение; не считать найденный текущим аудитором список исчерпывающим.

Приоритет внутри прохода: Sparky, Pizza Boxer, Sticky Fingers, Keyboarder, Wordplayer; затем остальные. Wander/Dither сейчас включены в первую очередь как уже подтверждённые общие дефекты.

## 6. Как переносить Random Lines и подобные инструменты

### Что найдено в оригинале

Основной кандидат — `lunnen/random_lines_generator/01/`: `index.html`, `styles.css`, `script.js`. Папки с суффиксами копий не смешивать с основной версией без отдельной сверки.

Canvas preview 3000 × 1000; экспорт — настоящий SVG из массива линий. Параметры: длина/ширина/количество, safe field, scale, round caps; gradient raster / image raster, параметры highlights и shadows, contrast, invert. Генерация намеренно запускается кнопкой Generate/Regenerate, а не на каждом движении параметра.

Логика, DOM, файлы, localStorage и геометрия находятся в одном `DOMContentLoaded`-замыкании. Есть внешний CoFo и Arial fallback в UI, общий ненеймспейсный ключ `randomLinesSettings`, случайность через `Math.random()`, цикл подбора до 100000 попыток с проверкой уже созданных линий. Это риски переноса, не повод одновременно переписывать математический алгоритм.

Отдельный подтверждённый дефект импорта имени: проверка `startsWith("s")` идёт раньше `startsWith("sf")`, поэтому `sf12` попадает в ветку масштаба и даёт `NaN`. Исправлять в новой копии отдельным тестируемым изменением; оригинал не трогать.

### Схема интеграции

```text
upgrade/framework/          общие компоненты, панели, действия, import/export UX
          ↑
upgrade/random_lines/       новый потребитель того же runtime
  app/                      адаптер настроек и связей UI ↔ model
  model/                    валидируемое состояние / восстановление
  engine/                   генерация линий, без зависимостей от UI
  renderers/                canvas preview и SVG export
  tests/ + fixtures/        геометрия, файлы, сценарии переноса
```

Это предлагаемая структура; эти папки ещё не созданы. Сам `framework/` внутрь нового инструмента не копировать. Отдельный адаптер позволяет сохранить частную математику и заменить только оболочку.

В репозитории также есть независимый переносимый пакет `upgrade/extracted/ui-garage/` (1.0.2). Восемь приложений его сейчас не используют. Не подключать новый инструмент к нему вперемешку с рабочим `upgrade/framework/`: иначе получится две расходящиеся системы UI. Полезные идеи декларативного адаптера, starters и тестовых состояний брать из пакета и переносить совместимые улучшения в рабочий framework с тестами. Полная смена runtime всех приложений — отдельное решение, не скрытая часть миграции Random Lines.

### R1. Зафиксировать поведение до переноса

- Инвентаризировать контролы, defaults, min/max/step, режимы, источник изображения, экспорт, reset и filename restore.
- Сохранить тестовые входы и SVG/линию-геометрию для обычного, gradient и image режимов. Случайность сделать управляемой в тестовом адаптере или зафиксировать массив линий; оригинальный код не менять.
- Зафиксировать, какие изменения требуют Generate, а какие обновляют отображение; измерить разумную загрузку и предельный случай.
- Включить плохие числа, пустое имя файла, `sf12`, scale, caps и отказ загрузки изображения. Ошибку оригинала описать отдельно от ожидаемой совместимости.

Готово: есть воспроизводимая база сравнения. Один скриншот случайных линий ею не является.

### R2. Изолировать копию и извлечь engine без редизайна

- Создать новый каталог только внутри upgrade, скопировать нужные исходники/локальные assets; никаких runtime-ссылок на lunnen и CDN.
- Разделить модель, генератор, preview и SVG export по минимальным швам. Сохранить порядок вычислений и количество вызовов RNG.
- Новый ключ хранения: например `upgrade:random-lines:v1`; не читать/писать старый `randomLinesSettings` автоматически. Миграцию старых настроек сделать явной операцией.
- Проверить модель → линии → canvas/SVG на прежних фикстурах. Отдельным изменением исправить парсер `sf` с тестом.

Готово: автономная новая копия с подтверждённой геометрией, оригинал не затронут.

### R3. Заменить оболочку на общие компоненты

- Панель Geometry: count, length, width, safe field, scale, caps. Доступные значения сохранить; numeric field не заменять range с более узким диапазоном.
- Панель Tone для gradient/image: группы **HIGHLIGHTS** и **SHADOWS** имеют смысл как парные параметры. Здесь оправдан заголовок группы Wordplayer; не добавлять разделители к каждому отдельному контролу.
- Панель Image: превью источника, contrast, invert; появление зависит от режима. File input использует общий UX, декодирование остаётся частным.
- Общий dock: ? / Generate (или Regenerate) / SVG ⌘E; JSON extras по J/О. Reset и restore имеют ясное место и подтверждение потери текущего состояния, если оно требуется. Не выдавать Generate за экспорт и не включать его в общий export feedback по префиксу ID.
- Сохранить явный Generate для тяжёлого расчёта. Live-обновление нельзя включать только потому, что другие инструменты лёгкие.
- Подключить общий registry действий, панели, summary, клавиатуру и варианты состояний; renderer не должен импортировать DOM-контроллеры.

Готово: общая оболочка, неизменные рабочие возможности, весь UI включён в лабораторию и аудит.

### R4. Честное сохранение и экспорт

- Имя SVG сейчас возвращает только часть параметров, а не точную случайную композицию и не исходное изображение. Сохранить legacy import, но не обещать полного round-trip.
- JSON v1 должен явно определять воспроизводимость: либо массив линий/модель результата, либо seed + версия алгоритма с проверкой совпадения. Seed в одиночку без контроля алгоритма недостаточен.
- Для image raster определить политику источника: встроенное изображение с ограничением размера либо явное требование повторного выбора. Не потерять источник молча при успешном сообщении об импорте.
- Проверить количество и координаты линий, ширину, linecap, масштаб, фон и art-colours в SVG. Цвет `#666` в изображении не перекрашивать как ошибку UI-палитры.
- Проверить объектные URL и повторный экспорт; освобождение ресурсов не должно опережать скачивание.

### R5. Приёмка и включение в индекс

Проверить границы/локальные зависимости, отдельное хранилище, все режимы и ошибки, реальный SVG/JSON round-trip, ограничения времени расчёта, новый аудит, отсутствие 404/console errors. Затем добавить рабочую ссылку в индекс и реестры проверок. Не превращать placeholder в активный до завершения этой приёмки.

Worker, spatial index и ускорение алгоритма — последующая отдельная задача с benchmark и проверкой результатов, не условие первого UI-переноса.

Этот же маршрут использовать для остальных старых инструментов: контракт функций → воспроизводимые исходные результаты → изолированный engine → общий UI через адаптер → артефакты и приёмка. Каталог общего framework не размножается.
