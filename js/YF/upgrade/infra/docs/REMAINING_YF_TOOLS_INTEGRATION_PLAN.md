## 2. Что исследовано и что ещё не проверялось

Проверены индексы, активные HTML/JS/CSS, параметры и режимы, инициализация, модели, генерация, экспорт, работа с файлами, клавиатура, хранение, внешние ресурсы. У Calendar дополнительно рассмотрены четыре SVG и способы их перечисления; у Chladni — звук, ручные режимы, кадр на паузе и README. Также проверены текущие API/рендереры `upgrade/infra/framework`, контракт UI, отдельный UI Garage и списки приложений в QA.

Это **исследование исходников**, не браузерная приёмка. Микрофон не включался, оригинальные приложения не запускались с записью их localStorage, экспорты на диск не выполнялись. В изолированных Node VM воспроизведены четыре проблемы/расхождения: Random Lines filename parser, маршруты экспорта Pattern 01, номера слоёв Asterisk, блокировка ручного X в Chladni. VM-заглушки подтверждают конкретный путь кода, не заменяют проверку настоящего браузера.

Первоначальный исследовательский проход создал только этот план. Последующая реализация INT-00/01 меняет каталог, индекс и QA внутри upgrade; исходники инструментов и framework в этом этапе не изменены.

## 3. Главный архитектурный выбор

**Новые приложения используют общий рабочий `upgrade/infra/framework/`. Не копировать framework в каждый инструмент и не подключать их к `upgrade/infra/extracted/ui-garage/`.**

UI Garage — независимый переносимый пакет, текущие восемь инструментов его не используют. Он полезен как источник проверенных подходов, но смешение двух runtime внутри upgrade вернёт исходную проблему расхождения интерфейсов. Переключение всех приложений на другой runtime было бы отдельным проектом.

Рекомендуемая структура приложения:

```text
upgrade/
  infra/framework/           один рабочий framework и versioned vendor
  <tool>/
    index.html               общая оболочка без старого полного CSS
    app/                     связывание UI, состояния и действий
    model/                   схема, валидация, versioned document
    engine/                  предметная математика без DOM
    render/                  preview и экспорт из одной модели результата
    presets/                 только если нужны этому инструменту
    assets/                  только его частные исходники
    tests/fixtures/          воспроизводимые входы и ожидаемые артефакты
    MIGRATION.md             baseline, исключения, проверки, остаток
```

Для небольшого инструмента не создавать пустые директории ради схемы. Главное — границы ответственности, а не число файлов.

### Общим становится

- Шрифтовой стек `-apple-system, BlinkMacSystemFont, Inter, Segoe UI, Roboto, sans-serif`, только 400/500; UI-текст #d2d2d2. Без Arial, CoFo и TT Commons в UI. Шрифты artwork не менять под видом унификации; служебные подписи, нарисованные в canvas, тоже считать UI.
- Панели, drag/stack, collapse/restore, неизменная высота и ширина свёрнутой панели, сокращение сводок и ellipsis.
- Обычные слайдеры/числа, toggles, dropdowns, цветовые поля, осмысленные групповые заголовки Wordplayer и spacing общего контракта.
- Загрузка/замена/удаление источника в панели управления. FileIntake владеет состояниями loading/error/reselect; частный декодер — приложением.
- Нижний ActionDock: `?`, экспорт, его опции, скрытые JSON extras. Не размещать там случайные управления источниками. Generate/Regenerate, Center, Start/Stop/Pause — в соответствующей панели, отдельно от экспорта.
- Единый реестр команд: кнопка, хоткей и справка используют одно описание; ⌘/Ctrl+E — основной экспорт, ⌘/Ctrl+J — JSON, ⇧⌘/Ctrl+J — JSON import, J/О — extras, ⌘/Ctrl+\ — collapse/restore, ? — шоткаты. Не возвращать ⌘0/⌘1.
- ExportFeedback: успех только после завершения создания артефакта и запуска скачивания, отдельные error/unavailable, быстрый повторный запуск. Не считать выключенную кнопку признаком экспорта.
- Namespaced storage, история и пресеты через общий API там, где они включены. Изоляция новых namespace от оригиналов и друг от друга.
- Граница **выходного листа** как preview-only элемент, отдельный от геометрии, сетки и выделения. Один CSS-пиксель независимо от zoom; не попадать в SVG/PNG.

### Частным остаётся

Генеративная математика, формулы и порядок RNG, диапазоны/единицы, топология узоров, точки магнитного поля, временное состояние анимации, выбор групп календаря, FFT и микрофон, правила растрирования, содержимое экспортов и legacy import. Не создавать универсальный «генератор всего».

Предметный **Scale** не становится **Zoom**: Scale меняет результат/экспорт, Zoom только просмотр. Это особенно важно для Random Lines, Rays и Asterisk.

### Важное ограничение текущего API

`ApplicationShell._initTarget()` сейчас создаёт только `CanvasTarget` или `SvgTarget`. Это не готовый host для p5. `CanvasTarget.beginFrame()` меняет размер буфера, очищает его и устанавливает DPR/zoom transform. Нельзя заставлять его и p5 одновременно владеть одним canvas.

Два безопасных пути:

1. **Native Canvas/SVG:** извлечь engine и использовать `defineTool` / штатный render target. Logical bounds отделены от viewport.
2. **p5:** в первой миграции сохранить частный renderer с одним владельцем canvas; подключить публичные Settings, SliderController, PanelManager, ActionDock, FileIntake/feedback по необходимости через небольшой app adapter. Если потребуется общий внешний render host, выделить opt-in capability и сначала проверить на одном статическом потребителе. Не притворяться, что такого API уже достаточно.

p5 1.4.0, 1.7.0 и 1.9.0 нельзя без проверки заменить одной новой версией. Первоначально — pinned локальные версии в `framework/vendor`, лицензии и checksums. Они подключаются только потребителями; p5.sound не должен загружаться в остальные инструменты. Консолидация версий и переписывание p5 на Canvas — отдельные оптимизации после parity.

## 4. Карточки инструментов

### 4.1. Rays Pattern — рекомендуемый первый перенос

**Прогресс 2026-09-22.** T.1/T.2: `rays_pattern_generator/` существует как migration preview, без общего UI. `infra/qa/migrations/rays/` содержит замороженный исходник, семь golden-сценариев, Node harness и тесты. Алгоритм действующего script не изменён. На T.3a добавлен отдельный `engine/scene.js`: чистая модель модулей/лучей/соединений, 11 новых тестов против legacy, всего 33. Следующий этап — T.3b, подключить Canvas/SVG к модели. Подробные ограничения и исходные дефекты — в [отчёте T.1/T.2](RAYS_T1_T2_BASELINE.md). Эти дефекты ещё не исправлены и не считаются принятой целевой логикой.

**Устройство.** Три активных файла, native Canvas 3000 × 1000 и отдельный SVG exporter. Общая регулярная раскладка модулей, лучи, соединения, шахматное смещение рядов. Живой пересчёт при изменении параметров. localStorage `rayPatternSettings`. Восстановление параметров из имени SVG. Внешние CoFo в CSS.

**Сохранить.** Разрешённые количества лучей `[3,4,5,6,8,10,12,14,16,18,20,24]`, а не все целые между 3 и 24; длину, толщину, gap, масштаб, горизонтальный/вертикальный шаг, caps, соединительные линии и фактическую логику смещения рядов. Три режима: обычный, gradient raster, image raster. В image mode — contrast/invert, собственная выборка яркости.

**Панели.** Geometry: длина/толщина/gap/count. Layout: масштаб/шаги/смещение/соединения. Tone: две группы Highlights/Shadows. Image: источник, contrast/invert. Не размещать каждый параметр в отдельном окне. SVG ⌘E и нужные export options — в dock.

**Работы.** Сначала извлечь одну модель списка модулей/лучей, которую читают preview и SVG. Вынести выбор допустимого ray count в явно тестируемую функцию. Затем заменить оболочку. Проверить реальное соответствие названия Offset Rows boolean-логике: код использует `!params.offsetRows` для смещения, нельзя просто перевернуть флаг из-за имени.

**Проверки.** Все допустимые count; caps; соединения on/off; смещение обеих полярностей; крайние клетки/clip; scale 0.1/1/3; gradient и image; неверный/повторный файл; legacy filename. Имя файла не содержит сам источник изображения — это не полный project round-trip. В текущем exporter создаётся Object URL без revoke; исправить жизненный цикл в новой копии.

### 4.2. Random Lines

**Устройство.** Три активных файла; native Canvas 3000 × 1000 → SVG из массива линий. Состояние, DOM, генерация и импорт находятся в одном замыкании. Ненеймспейсный `randomLinesSettings`. Явный Generate/Regenerate; исходная страница намеренно не генерирует тяжёлый рисунок автоматически.

**Сохранить.** Число/длина/толщина, safe field, scale, caps, ordinary/gradient/image, Highlights/Shadows, contrast/invert. Сохранить различие изменения параметров, модификации имеющихся линий и полной регенерации. Не включать живую тяжёлую генерацию только из-за подключения общих слайдеров.

**Панели.** Geometry с Generate/Regenerate и состоянием актуальности результата; Tone с Highlights/Shadows; Image. Числовые поля можно связать со стандартными диапазонами, но не сужать реальные ограничения. Reset/legacy filename restore — в панели. В dock SVG и JSON extras, не Generate.

**Подтверждённая ошибка.** В `restoreSettingsFromFileName()` ветка `s` проверяется раньше `sf`: имя `random_lines_w8_l24_c3000_s1.0_sf12.svg` даёт `scale=NaN`, safeField отсутствует. Воспроизведено в VM. Исправление отдельным шагом в новой копии с regression test.

**Риски.** Math.random и проверка safe fields со сравнением кандидата с существующими линиями; предел 100000 попыток. Количество фактически размещённых линий может быть меньше запрошенного — это надо показывать, а не тихо считать успехом. Воспроизводимость определяется массивом результата или seed + версией алгоритма, а не одними настройками.

**Проверки.** Seeded RNG в тестовом адаптере с прежним порядком вызовов; геометрия safe fields; 0/12/предельное поле; count около оптимизационного порога 1000 и после него; export до генерации; старый рисунок после изменения настроек; парсер `sf`; filename не восстанавливает точную случайную сцену и image asset. Worker/spatial index — после измеренного baseline, отдельным изменением.

### 4.3. Pattern 02

**Устройство.** p5 1.7.0 из CDN, полноэкранный canvas, `noLoop()` / `redraw()`, собственный SVG builder. Шесть слайдеров, три checkbox; локальные undo/redo стеки до 50 состояний. Хранения между запусками не найдено. Экспорт использует размеры окна.

**Сохранить.** Размер элемента, относительные corner radius/width/spacing, длины A/B, caps, checkerboard, обе фигуры B. Общий обход сетки уже используется preview/export — сохранить его. Значение Length A=0 специально превращается в 0.01, не «исправлять» это без сравнения результата.

**Панели.** Shape: геометрия A/B; Layout: size/spacing/checkerboard; история через общие команды. Дополнительные групповые заголовки оправданы только если помогают отличить A и B. Нижняя кнопка SVG ⌘E.

**Работы.** Использовать как первый p5-потребитель, поскольку он статический. Локализовать 1.7.0, разделить state/geometry/render/UI, затем подключить общий UI без второго canvas owner. Историю перевести на транзакции одного жеста, сохранив как минимум нынешние undo/redo; мышь, touch и клавиатура должны одинаково фиксировать изменения.

**Проверки.** A/B, оба caps, оба шахматных состояния, оба B, 0/100 процентов, минимальный size, границы рисунка; Canvas и SVG при одинаковом logical size; resize отдельно от изменения документа. Проверить соответствие p5 cap-констант SVG linecap. Экспорт «размер окна» сперва зафиксировать как legacy-режим; постоянный размер документа — явное улучшение, не молчаливая замена.

### 4.4. Asterisk Pattern

**Устройство.** Три runtime-файла, native Canvas 1920 × 1080; около 1700 строк JS, много повторяющейся геометрии в preview и SVG. `coding_module_1920x1080.svg` лежит рядом, но runtime-ссылки на него не найдены: оставить как reference fixture, не загружать обязательно в приложении.

**Сохранить.** Thickness, corner radius, layers 0–100, масштаб `1 : 2^n` для n=0…7, rounded caps, tessellation/axes, модульную сетку. Точные исходные опорные координаты и тройное вращение не округлять «для чистоты».

**Панели.** Shape: толщина/радиус/caps; Repetition: layers/tessellation/масштаб; Grid — видимость. Не путать масштаб композиции с zoom. Короткая сводка слоя/масштаба, SVG ⌘E.

**Подтверждённое расхождение.** При одном слое в axes-режиме preview вызывает слой `[1]`, SVG `[0,1]`. Нулевой слой проходит обычный exportDuplicateLayer, не early-return tessellation. VM подтвердила последовательность. Проверить и устранить лишние совпадающие копии отдельным шагом, а не принять дубликаты за новый эталон.

**Сетки и шрифты.** В отличие от служебной рамки листа, здесь Grid уже участвует в SVG; нельзя вырезать его общим export cleanup. Видимые подписи сетки используют Arial, SVG описывает такой же font rule. Надо классифицировать подписи как служебные, заменить их UI-шрифт; включение самой сетки в файл пока сохраняется. Предлагаемое последующее улучшение — отдельная явная опция Include grid, но это изменение поведения, не автоматический перенос.

**Проверки.** Layers 0/1/2/7 и ограниченный стресс-тест, tessellation/axes, scale 1:1…1:128, радиус 0 и clamp, caps, grid; число path/копий, координаты, порядок transform, сохранение толщины в export. Сначала получить тесты существующих функций, затем объединять preview/export через scene geometry. Не запускать без лимита синхронный максимум 100 слоёв в основном UI.

### 4.5. Pattern 01 — один инструмент, пять режимов

**Устройство.** Восемь активных файлов: HTML/CSS и шесть JS. Native Canvas, Google Fonts Inter 400/700. Пять вкладок, часть UI генерируется динамически. Режимы существенно различаются:

1. **Diagonal Grid:** регулярные отрезки, размеры документа, длина/толщина/spacing/angle/caps; магнитный курсор, закреплённые точки со своей силой/радиусом, частная история точек.
2. **Fibonacci Dotted Circle:** count/radius/point size/spiral factor, детерминированная формула.
3. **Voronoi Distribution Circle:** случайные точки и итерационное отталкивание внутри круга.
4. **Voronoi Rectangle:** случайное распределение/отталкивание внутри прямоугольника, ratio.
5. **Fibonacci Rectangle:** другой способ пересечения луча с границами прямоугольника, ratio/spiral factor.

Названия Voronoi не означают, что нужно подменять нынешнюю математику библиотекой построения диаграмм Вороного. В текущем коде это распределение точек/отталкивание.

**Панели.** Один общий переключатель режима, один output dock и активный canvas host. Режимные controls находятся внутри общих панелей. Diagonal Grid получает отдельную группу Magnetic / точки. Не превращать пять режимов в пять новых ссылок без отдельного решения.

**Подтверждённые проблемы.** Общий ⌘E не содержит ветку magnetic-rect, а в Rectangle вызывает `window.rectangleModule.exportSvg()`, которого нет в возвращаемом API. Обе проблемы воспроизведены в VM. Частный document-level keydown магнитного режима не ограничен активной вкладкой; после миграции действие должно принадлежать активному режиму и не перехватывать ввод.

**Риски.** Часть режимов генерирует заново при смене вкладки/resize; круговые режимы привязаны к экранным размерам и могут уменьшить radius при resize, прямоугольные имеют свои logical dimensions. Магнитный preview учитывает курсор, SVG — закреплённые точки. Это разные виды временного состояния; не пытаться исправить их одним универсальным `render()` без контракта.

**Работы.** Сначала общий host и один режим Fibonacci Circle. Затем Fibonacci Rectangle, два случайных режима, последним Diagonal Grid. Для каждого — отдельная модель и тесты. В первой версии сохранять параметры режимов и согласовать политику сохранения случайной композиции при переключении; предложенный целевой UX — восстановление режима без неожиданной регенерации, но это отмечается как осознанное отличие от оригинала.

**Проверки.** Пять кнопочных/клавиатурных экспортов; состояние при переключении; центр/радиус/ratio/point count; seeded fixtures для отталкивания; magnet point add/clear/undo и радиус/сила; кратность регистрации обработчиков. Не «оптимизировать» O(N² × iterations) вместе с переносом интерфейса.

### 4.6. Calendar Randomizer

**Устройство.** Основной код и CSS внутри HTML; `list-svgs.js` перечисляет четыре локальных `source/calend_0*.svg`. Есть PHP-файлы, но активная страница использует JS-список и XHR, а не PHP. Для static upgrade серверный runtime не нужен.

**Сохранить.** Выбор четырёх календарей, цвет рисунка/фона, диапазон смещения, easing и длительность, Randomize/Reset, SVG. Space и Backspace существуют как частные команды — при переносе разрешать только вне editable-target и без конфликта с панелями/браузером. Здесь Space — Randomize, не Pan.

**Панели.** Source/template; Appearance (два цвета); Motion (range/easing/duration и Randomize/Reset). Внизу SVG ⌘E и JSON extras. Иконка сворачивания справа отдельно больше не нужна — общая панель.

**Подтверждено кодом.**

- exportSVG заново берёт Math.random, использует другой набор элементов, чем preview, и удаляет style. Это не сохранение текущей композиции.
- initializeCalendar вызывается при каждой смене SVG и каждый раз добавляет listeners кнопкам/цветам/keydown/collapse. Старые подписки не снимаются.
- `document.querySelector('svg')` и другие глобальные svg-селекторы выберут иконку framework, если она окажется первой. Всё должно быть scoped к artboard.
- Фон меняется у body, а не является самостоятельной частью экспортной модели. Не считать автоматически, что он есть в файле.
- Общий ключ `controlsCollapsed` нарушит изоляцию, если перенести его без namespace.

**Работы.** Локальный JSON manifest вместо PHP; parser/validated template model и стабильные ID целей анимации; отдельные base transforms, offsets, colors и motion state. Одна init/destroy подписка. Защита от устаревшего ответа при быстром выборе шаблонов. Загрузка только известных локальных assets; загрузка произвольного SVG пользователем — отдельная возможность с sanitization, не часть обязательной миграции.

**Предлагаемое изменение поведения, требующее принятия.** SVG сохраняет уже выбранную композицию. Во время перехода сохранять конечное целевое состояние с понятным сообщением, а не случайный промежуточный кадр. Если нужна старая операция «новая случайная композиция сразу в файл», дать ей отдельное название, не называть обычным Export. Подтвердить до реализации экспортного этапа.

**Проверки.** Все четыре шаблона, 20 переключений без размножения действий; один клик — один экспорт; nested groups/defs/base transforms; актуальность загрузки при быстрых переключениях; Randomize→Reset; repeat export без новой случайности в новом режиме; выбранные цвета и фон; экспорт при проигрывании transition. История должна хранить offsets, а не только силу рандомизации.

### 4.7. Hyperspace

**Устройство.** p5 1.4.0 из CDN, fullscreen canvas, непрерывный draw. Частицы/линии с origin, длиной, скоростью и временем создания. Три точки схода: визуальная, фактическая и целевая; движение с инерцией. PNG строится на отдельном graphics buffer без индикатора паузы.

**Сохранить.** Count, opacity, fade, segments, thickness, width growth, reverse wedge, reset radius, speed, трёхточечный цветовой gradient, Center, pause и drag точки схода. Точка рождения уже существующих линий не должна прыгать при переносе target. PNG — текущая композиция, а не её случайная регенерация.

**Панели.** Lines/Appearance; Motion (speed/radius, pause, center); Gradient с тремя общими color fields. Не добавлять SVG/MP4 только потому, что framework умеет другие экспорты: обязательный формат здесь PNG.

**Работы.** Локальный pinned p5 и adapter, один цикл кадра, явный destroy. Отделить simulation state от UI и render. Зафиксировать RNG и временную последовательность в тестах; переход на deltaTime вместо текущего шага кадра не смешивать с переносом. PNG получает snapshot сцены. Старый feedback кнопки заменить explicit controller.

**Проверки.** Pause/resume, center при движении и паузе, drag вне панелей, resize, оба wedge, gradient on/off, крайние segments/count, PNG без UI. Старый hit-test исключает только прямоугольник `.controls`: после появления нескольких панелей и dock надо исключать все UI surfaces. Старый Space перехватывается без проверки editable target — заменить общим action routing. Правильный cleanup временного buffer, callbacks, listeners и animation loop.

**Сохранение.** JSON настроек не обещает воспроизведения текущего кадра. Для snapshot нужны параметры + stars/origins + точки схода + временное состояние + logical dimensions. В первой версии можно поддержать settings-only с явной маркировкой, но не выдавать это за точный project restore.

### 4.8. Chladni Sound Pattern

**Устройство.** p5/p5.sound 1.9.0 из CDN. Canvas 600 × 600, PNG 1200 × 1200. Статический ручной рисунок и audio-reactive режимы X/Y, FFT 1024, sensitivity/smoothing, threshold, gradient/noise/invert/diagonal terms. Start/Stop/Pause, кадр lastFrameState. В README описан интерактивный текст, но в актуальном HTML/sketch этого UI и логики не найдено — не добавлять новую функцию ради соответствия устаревшему README.

**Панели.** Pattern (mode X/Y и отдельный Audio reactive для каждой оси); Appearance (contrast, gradient, noise, invert, diagonals); Audio (Start/Stop/Pause, sensitivity/smoothing, статус разрешения). Внизу PNG ⌘E; микрофон не запускается кнопкой экспорта.

**Подтверждено кодом/VM.**

- Общий `toggleSliderInteractivity(enabled)` блокирует обе оси: при X=manual, Y=reactive обработчик Y может выключить и ручной X. Воспроизведено в VM. Доступность каждой оси должна вычисляться отдельно.
- Start выставляет isRunning сразу после вызова mic.start(), не из callback успешного запуска микрофона. Promise userStartAudio не равен факту получения mic stream; нужны requesting/running/denied/error.
- При работающем звуке preview использует dynamicThreshold, а PNG получает thresholdValue. Для точного снимка надо использовать то же состояние кадра.
- p5 keyPressed возвращает false безусловно; текущие keyboard/editable сценарии нельзя переносить как есть.
- В draw выполняются полные пиксельные циклы, создаётся graphics buffer для noise и печатается console.log на каждом кадре. Производительность — самостоятельная зона проверки.

**Работы.** Начать с ручного режима без доступа к микрофону. Затем injectable AudioSource: тестовая последовательность FFT/levels и отдельный настоящий mic adapter. Математика и FFT interpretation остаются частными; в framework — максимум общий permission/status UI, не знание частотных диапазонов Chladni.

**Безопасность и lifecycle.** Запрашивать микрофон только по явному Start; не запускать при восстановлении JSON или открытии UI-аудита. Stop/destroy/page exit освобождают принадлежащие приложению tracks и callbacks. Pause замораживает визуальный кадр; явно решить, продолжает ли при этом работать микрофон (legacy Pause не вызывает mic.stop). Никаких аудиозаписей, передачи звука или автоматического сохранения потока. Ошибки отказа/отсутствия устройства показываются без ложного Running. Нужны secure-context сценарии localhost/HTTPS.

**Проверки.** Сначала детерминированные static pixels/noiseSeed и записанная в fixtures числовая последовательность FFT, а не запись голоса пользователя. X/Y все четыре комбинации manual/reactive; stop/pause/export; разрешение отклонено/устройство отсутствует; повторный Start/Stop; PNG того же кадра в 2×; очистка ресурсов. Настоящий микрофон — отдельная ручная приёмка с разрешением пользователя. Это самый рискованный кандидат.

## 5. Общие риски, которые нельзя прятать в переносе

### Изоляция

- Чтение оригиналов разрешено для исследования/копирования; запись только `upgrade/**`.
- Копировать выбранные runtime-файлы и реально используемые assets, не весь архив и не чужой framework. Не делать внешние symlink или runtime-ссылки на `../lunnen`/`../muted`, `/fonts`, CDN.
- Не читать и не мигрировать автоматически старые `randomLinesSettings`, `rayPatternSettings`, `controlsCollapsed`. В upgrade не допускается восстановление чужого namespace при совпадении origin.
- Проверить HTML/CSS/JS, nested imports, workers, fonts, SVG href/CSS url, fetch, storage, build scripts. Одного поиска строк CDN недостаточно. Запуск из перенесённой временной копии upgrade должен работать без доступа к исходникам.
- Для онлайн-зависимостей восьми текущих приложений (например Google Sheets) сохраняется прежний явный opt-in. Это не разрешение новым генераторам подтягивать fonts/scripts извне.

### Модель документа и результат

Разделять settings, transient UI, rendered result и external source. Число лучей не заменяет массив случайных линий; intensity не заменяет offsets календаря; FFT-параметры не являются сохранённым кадром. Экспорт читает зафиксированное состояние, не генерирует новую сцену незаметно.

Если JSON включён: `toolId`, `schemaVersion`, `algorithmVersion`, document size, settings, необходимые результаты/источники. Валидация до мутации, лимиты размера, отказ от чужого toolId, атомарный rollback. Settings-only и project snapshot имеют разные обещания. Импорт изображений требует явной политики: embed с лимитом либо сообщение о необходимости повторного выбора.

Не добавлять всем сразу presets/share/history/JSON только для одинакового числа кнопок. Сначала базовая parity и общий UI. Потом минимально достаточное сохранение для конкретного инструмента с проверяемым round-trip. Если JSON реализован, он обязан соблюдать общий keyboard/visibility contract.

### Предпросмотр и файлы

Зафиксировать отдельно размеры документа, viewport и DPR. Canvas preview не является автоматически экспортной моделью. Не заменить настоящий SVG растровой картинкой внутри SVG. Не менять чёрный/прозрачный фон исходного формата без явного решения. Не экспортировать help, pause label, preview edge или magnetic handles. Domain grid Asterisk — отдельный случай: сейчас часть формата.

## 6. Подготовка общего framework и QA

Сейчас `APPLICATION_CAPABILITIES.json`, `check-boundaries.mjs`, `check-ui-contract.mjs`, `check-capability-manifest.mjs`, другие inventories и UI-аудитор явно перечисляют восемь приложений. `UnifiedUiController` также знает старые tool IDs. Простого добавления восьми папок недостаточно: новые инструменты могут вообще не попасть в проверки.

### INT-00 — согласовать объём и зафиксировать baseline

1. **Готово:** пользователь подтвердил все восемь инструментов.
2. Проверить чистоту/текущие параллельные изменения; сохранить source manifest для выбранных runtime roots и assets, с путями и SHA-256 каждого файла.
3. Запустить актуальные тесты текущих восьми: tier1/tier2, check:boundaries, check:storage, check:ui-contract, check:actions, check:file-intake, check:ranges/check:toggles, check:capabilities, check:component-lab. Отдельно smoke в браузере.
4. Не переносить в baseline старые ошибки как будто они прошли проверку. Блокеры общего UI устранить до подключения новых потребителей; несвязанные проблемы отдельного старого инструмента записать явно и не смешивать с первой миграцией.

Готово: определён состав, исходники, реальные исходные ошибки и стартовая точка; оригиналы не изменены.

Текущий статус: per-file baseline сохранён в `infra/qa/migrations/SOURCE_BASELINE.json`; исходные замечания и результаты первого запуска сохранены в отчёте INT-00/01. Её причина остаётся открытой; общий console gate и полная приёмка всех состояний/mobile не заявляются. См. INT-02.

### INT-01 — единый каталог и критерии подключения

1. На основе существующего capability manifest ввести один каталог инструментов: id, name, group, entry, state planned/migrating/accepted, capabilities, reference viewport и app-specific test contract.
2. Индекс и выбор в UI-аудите получают список из одного источника. Активная ссылка появляется только у accepted.
3. Runtime-проверки должны включать migrating-приложение с первого шага копирования, даже пока его нет в публичном индексе.
4. Не ослаблять старые assert «8» простым удалением чисел: отдельно защитить набор исходных восьми и адресные инварианты каждого нового инструмента. Каталог не должен сам себе служить эталоном количества контролов.
5. Не переписывать исторические gate-отчёты и source snapshot восьми приложений для получения зелёного результата. Создать отдельный migration manifest/отчёты для нового набора.

Готово: тестовый planned entry не публикуется, migrating проверяется, accepted появляется ровно один раз в правильном разделе; текущие восемь не пропадают и не меняют адресов.

Текущий статус: **готово для первого переноса**. `TOOL_CATALOG.json` — единственный действующий каталог навигации/QA. Он ссылается на неизменённый capability manifest исходных восьми и отдельные новые контракты. Индекс и select аудитора механически создаются из него (`npm run catalog:sync`); `check:boundaries` также проверяет их актуальность. `planned` не запускается, `migrating` сразу входит в проверку изоляции и UI-аудитор. 10 тестов политики каталога прошли. Это не заменяет предметные tests/fixtures T.1 каждого нового инструмента.

### INT-02 — общий UI host и действия без новых веток по имени

1. Проверить достаточность публичной регистрации app title, панелей/сводок и команд, чтобы новый потребитель не требовал ещё одного hardcoded имени в UnifiedUi.
2. При необходимости добавить opt-in config для новых приложений. Старый compatibility path оставить до его отдельной миграции; нельзя требовать переписать восемь инструментов одновременно.
3. Кнопки, меню ? и keyboard binding получают общие action descriptors с явными `run`, `enabled`, `kind`, group. Generate и mic actions никогда не проходят через export feedback по совпадению имени ID.
4. Команды учитывают editable/composition/repeat/modifiers/русскую раскладку/открытый dialog. Один вызов на жест. При появлении собственных Space/Escape-команд согласовать приоритеты; не включать стандартный Space-pan поверх Pause/Randomize.
5. Lab и UI-аудитор используют тот же CSS и показывают normal/hover/focus/disabled/loading/error, dynamic mode и collapse. Добавить source intake, режимную панель, долгую генерацию и mic state как сценарии, а не отдельные копии идеального CSS.

Готово: один небольшой native Canvas fixture подключает общий UI без имени приложения внутри framework; re-init не удваивает listeners. Текущие восемь проходят регрессию.

Текущий статус: **реализовано и проверено на native Canvas fixture; console gate аудитора открыт**. Публичный `ToolUiController`, общий descriptor→button/help/keyboard, explicit export feedback, lifecycle и mode guards. Стенд `infra/qa/ui-host/` использует общий CSS, настоящую PNG-encoding операцию и явно обозначенные симуляции source/JSON/audio; реальные адаптеры проверяются при переносе соответствующего приложения. Подключение, ограничения и реальные результаты — [INT-02](INT_02_SHARED_UI_HOST.md). Следом диагностика сообщения аудитора и независимая подготовка Rays T.1.

| 4 | Asterisk Pattern | Мало controls, но сложная геометрия и два варианта повторения | 5–8 |
| 5 | Pattern 01 | Пять самостоятельных режимов и magnetic interaction | 8–12 |
| 6 | Calendar Randomizer | SVG templates, анимация и требующий решения export semantics | 5–8 |
| 7 | Hyperspace | Непрерывная анимация, snapshot и pointer ownership | 6–9 |
| 8 | Chladni Sound Pattern | Audio permission/lifecycle, динамический raster и реальное устройство | 8–12 |
| 9 | Общая приёмка и подготовка публикации | 8 старых + выбранные новые, isolation/artifacts/browser | 3–5 |

Это исходная грубая оценка по коду, не обещание скорости модели: для подтверждённых восьми 57–87 итераций ≈ 38–58 часов активной работы, включая подготовку. Остаток уточнять после первого пилота; не считать уже выполненную подготовку повторно. Прежний график «одна итерация раз в 5 часов» не означает, что автоматические ночные запуски настроены.

### Одинаковая последовательность внутри каждого пакета

**T.1 — контракт и fixtures, без замены UI.** Список режимов/controls/defaults/ranges/units, генерация при input/change/Generate, размеры/фон/форматы, legacy storage/import, target states. Fixtures с seed/RNG stream, готовыми геометрическими массивами, изображениями или числовой аудиопоследовательностью. Список известных ошибок отделён от expected parity.

**T.2 — изолированная копия.** Только выбранные runtime-файлы и assets, локальные пути, новые namespace, отсутствие runtime-связей с оригиналом. Подключить migrating entry к boundary checker сразу. Пока не включать ссылку в индекс.

**T.3 — разрез по минимальным границам.** State/schema, engine, preview, exporter и adapter. На этом шаге не менять формулы, defaults, RNG order и пользовательскую генерацию. После каждого извлечения сравнить геометрию/артефакт с T.1.

**T.4 — исправить подтверждённые исходные ошибки.** Отдельные тесты и маленькие изменения: например sf parser, missing shortcut route, duplicate listeners, frame snapshot. Для спорного результата сначала принять правило. Не обновлять baseline лишь потому, что новый результат отличается.

**T.5 — общий UI.** Заменить legacy controls/panels/dock через общие классы и callbacks. Удалить старый глобальный CSS и inline UI overrides; не перекрывать их ещё одним слоем `!important`. Сохранить private presentation только там, где есть документированная специфика.

**T.6 — actions, lifecycle, state IO.** Клик/хоткей/help, реальный feedback, file states, source cleanup; история/JSON по выбранному объёму, без выдуманных обещаний round-trip. Панели и transient view не меняют artwork.

**T.7 — приёмка одного инструмента.** Unit + artifact + браузерные состояния; все приоритетные старые потребители затронутого общего компонента; затем accepted entry и активная ссылка. Commit/push — только при отдельном разрешении пользователя, не автоматически из этой инструкции.

Каждый T.n можно разбить на несколько 40-минутных итераций. Не требуется закончить одну фазу любой ценой за 40 минут. Передача следующему исполнителю: что изменено, что проверено, какие файлы разрешены, известный остаток и точная следующая маленькая задача.

## 8. Обязательная приёмка

### UI и взаимодействие

- Desktop 1440×900, 1280×800, 1024×768; при необходимости меньшая высота, scroll панели. Мобильная приёмка по прежнему обязательна для Sparky; не обещать новые mobile-ready инструменты без отдельной задачи.
- Те же font stack/400–500, button sizes/states, sliders, numeric fields, pills без растягивания по строке, заголовки групп и вертикальный ритм.
- Статусы empty/loading/error/ready, repeated file, длинное имя, недоступное действие; dropdown open/closed без изменения ширины; collapsed summary не расширяет панель.
- Centered dock с нижним отступом, help и JSON extras, soft success, немедленный безопасный повторный запуск; keyboard-driven focus.
- Режимные panels/controls после нескольких переключений; один gesture — одно действие. Поля ввода и имена файлов не запускают горячие команды.
- Для canvas: DPR 1/2, resize, logical bounds и screen coordinates; zoom не меняет документ/экспорт. Не сохранять service edge, pause label и handles.

### Данные, файлы и производительность

- SVG остаётся векторным; проверены размер/viewBox, количество и координаты примитивов, transform/linecap/width, фон и intentional grid.
- PNG: dimensions, alpha/фон, тот же frame/model, результат после encoder completion, cleanup URL/buffer.
- Для случайности сравнение по фиксированному входу/состоянию, а не pixel diff двух разных рисунков.
- Если есть JSON, полное сохранение всех обещанных параметров/результата/источника; повреждённый/чужой/слишком большой файл не меняет документ.
- Heavy generation замеряется на согласованных данных. Не расширять UI диапазоны и не менять алгоритм ради «скорости» одновременно с parity.
- Init/destroy/re-init и смена страницы не оставляют timers/listeners/workers/graphics/audio tracks. Отмена долгой операции не уничтожает предыдущий годный результат.

### Общая регрессия и выпуск

- Исходные восемь не потеряли controls, шоткаты, артефакты или адреса; Sparky mobile отдельно.
- В изолированной копии upgrade все выбранные новые инструменты работают с отключённой внешней сетью; microphone-сценарий отдельно. Никаких чтений соседних `lunnen`, `muted`, `othersite-ui-framework`.
- Нет 404/uncaught console errors в принятых сценариях. Результат статического checker не выдавать за свежий browser run.
- Отчёт содержит commit/dirty или hashes, время, браузер, viewport, fixture, выполненные команды и непроверенные случаи.
- Rollback отдельного инструмента: вернуть его предыдущую принятую версию/placeholder и соответствующую catalog entry. Общий framework нельзя откатывать вслепую, если другой инструмент уже зависит от его новой capability; такие изменения версионируются и сохраняют совместимость.
