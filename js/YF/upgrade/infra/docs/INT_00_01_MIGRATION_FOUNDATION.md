# INT-00/01 — подготовка переноса восьми инструментов

Дата: 2026-09-22. Рабочая основа: `ac4b5c9d6dfb039f86f2c342e5151e4db9fd6498` + изменения этого этапа, без commit/push. Node v24.11.1. Изменения только в upgrade; код действующих генераторов, framework и оригиналов не менялся.

## Сделано

- Пользователь подтвердил все восемь новых инструментов.
- `TOOL_CATALOG.json`: 16 записей, 8 accepted + 8 planned, группы Lunnen/Muted, адреса, reference viewport и ссылки на capability contracts.
- `APPLICATION_CAPABILITIES.json` оставлен контрактом исходных восьми: это не второй редактируемый каталог навигации. Старые acceptance manifests и SOURCE_MANIFEST не переписаны.
- `qa/migrations/CONTRACTS.json`: исходный renderer, режимы, форматы, обязательные сценарии и известные исходные проблемы каждого нового инструмента. Пока это требования, не свидетельство приёмки.
- `qa/migrations/SOURCE_BASELINE.json`: 32 выбранных файла, 791667 байт, SHA-256 каждого; включает четыре календарных SVG. Внешние p5/p5.sound пока не локализованы. Источники определены реальными ссылками YF, включая `/01/`, а не случайной соседней версией.
- `catalog/registry.js`: общие правила отображения и проверки статусов. Индекс и select UI-аудита генерируются из одного источника, работают без загрузки каталога через fetch.
- Изменение `planned → migrating` включает runtime-проверку и выбор в аудите, но не ссылку в индексе. Пока общий UI не подключён, аудитор показывает отсутствующие компоненты как непроверенные, а не блокирует доступ к рабочему окну.
- Каталог запрещает держать уже скопированную папку в planned. Удаление папки старого инструмента также вызывает ошибку. Для accepted новых приложений нужны unit/artifact/browser evidence; запись статуса сама по себе не является выполнением приёмки.
- `check:boundaries` проверяет каталог, актуальность обоих HTML-списков и изоляцию всех migrating/accepted приложений; дополнительно охватывает каталог и код самого аудитора.
- Исходные восемь защищены отдельными ожидаемыми IDs, адресами, порядком, приоритетной пятёркой и mobile только Sparky. Новые записи не могут тихо заменить старые.

## Команды для следующих итераций

```sh
npm run catalog:sync
npm run check:migration-foundation
npm run migration:sources:check
```

Выполнять из upgrade. Первая команда механически меняет только отмеченные HTML-регионы индекса и аудитора. Вторая не обращается к исходникам вне upgrade. Третья **явно читает оригиналы** для сверки provenance; она отделена от runtime/isolation gate, не пишет ни в оригиналы, ни в baseline. При расхождении hashes сначала изучить изменения, не обновлять baseline автоматически.

Перенос конкретного приложения: добавить только выбранную копию, одновременно поставить migrating и этап isolated-copy в контракте. Общие UI/артефактные тесты каждого нового приложения добавлять на T.1–T.7; старые тесты восьми не покрывают новую математику автоматически. accepted и активная ссылка — только после реальной приёмки, а не потому, что checker распознал папку.

## Открытый остаток baseline — не скрывать

1. **Pulsar / версия UI.** `check-ui-contract` ожидает `unifiedUiAutoInit.js?v=uiq-2`, фактическая страница подключает `uiq-3`. Общий UI в браузере работает. Это расхождение конкретной проверки, не подтверждённое отсутствие контроллера. Согласовать ожидание с текущей схемой подключения, не откатывать runtime ради строки.
2. **Keyboarder / exporter.** `check:actions` ищет буквальные `exportSVG()`, `exportPNG()`, `exportPDF()` в tool.js. Сейчас методы обёрнуты через массив имён и динамическое обращение; export-feedback и SVG tests проходят. Проверять действительный контракт вызова, не наличие старой формы записи. Эта проверка остановилась на первом assert, последующие также нужно выполнить после исправления.
3. **Pulsar / ranges.** В HTML 7 ranges, inventory ждёт 8. Сначала установить по истории, какой контрол удалён/заменён и почему; не менять 8 на 7 и общие суммы без адресной проверки параметра.
4. **Wordplayer / navigation.** Аудитор измерил `line-height: 16px` у `.mode-nav-back` против `normal` у Sparky. Размер кнопки и прочие проверенные свойства не дали отклонений. Нужно визуально подтвердить влияние и согласовать общее правило; различие вычисленного CSS ещё не доказывает сдвиг текста.
5. **Lifecycle / console.** Во временной QA-вкладке один раз зарегистрирована ошибка `MutationObserver.observe: parameter 1 is not of type Node` (08:58:21 UTC). Сообщение без stack и URL инструмента; источник пока не доказан. В framework есть observe(document.body), но нельзя объявлять именно его причиной без воспроизведения. Проверить загрузку/смену iframe и init/destroy, получить точную привязку. Все восемь замеров завершились, но «console clean» не заявляется.

INT-01 готов; INT-00 собрал baseline, однако его общий зелёный gate не закрыт. До первого нового UI-потребителя разобрать этот остаток. Следующий этап — INT-02, затем Rays T.1 (fixtures и контракт геометрии/экспорта). Ни один из восьми новых инструментов пока не перенесён и не опубликован.
