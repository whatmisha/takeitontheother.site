# NPV — версия 03

Оптимизированная копия `website/02`. Исходники и используемая геометрия находятся внутри `03`; изменения этой версии не затрагивают генератор и бэкап. Снимок зависимостей генератора хранится в `runtime/`.

## Запуск и сборка

Из самой папки `03` (её можно переносить и переименовывать):

```sh
npm ci
npm run build
npm run preview
```

Предпросмотр сборки: <http://127.0.0.1:8003/>. Для другого порта используйте переменную `PORT`.

Для исходной версии без сборки запустите из `03` команду `python3 -m http.server 8004` и откройте <http://127.0.0.1:8004/>. Нужен HTTP-сервер: открытие `index.html` через `file://` не поддерживает module worker.

Исходная версия также работает через существующий сервер проекта: <http://127.0.0.1:8001/website/03/>.

Публикуется содержимое `website/03/dist/`. Оно автономно: доступ к `src/`, `02/`, тестам и `node_modules` не требуется. Папка `dist` генерируется заново при сборке.

## Что изменено

- Плотность сферы по-прежнему вычисляется при загрузке для фактического размера: диаметр 4 CSS px, зазор не меньше 6 px. Расчёт перенесён в module worker, с кэшем трёх последних размеров и очередью, оставляющей только последний запрос при быстром resize.
- Общая последовательность осей создаётся лениво; логотип с кольцевой раскладкой её больше не рассчитывает. Сравнение кандидатов через косинусы сокращает вычисления, сохраняя исходный порядок и обработку равных значений.
- Worker отправляет раскладку до загрузки географических данных. Земля и регионы поступают следующим сообщением; устаревшие ответы после resize отклоняются. При недоступности worker есть резервный путь.
- Единственный обработчик скролла обновляет текст в кадре отрисовки планеты. Положение текста вычисляется непосредственно из скролла, без дополнительного сглаживания. Размеры блоков измеряются при изменении размеров, неизменившиеся стили и ARIA-атрибуты не переписываются.
- При отрисовке сферы пропускаются точки вне видимой части панели, одинаковые размеры эллипсов рассчитываются один раз за кадр.
- На третьем экране через 600 мс после завершения перехода в плоскую сетку запускается Search из Flat → Talent, с `Movement step = 2`. Цикл длится 10 секунд и повторяется; при уходе с экрана воспроизведение сбрасывается, при возврате снова выдерживается задержка. Управления фигурой от курсора нет. Точки остаются серыми, диаметром 4 px; масштаб Person — 300%.
- Search использует локальные `runtime/animation/personSearch.js` и `personMotion.js`. План маршрутов рассчитывается один раз на размер панели; базовая сетка и соответствие её точек сфере переиспользуются. В скрытой вкладке время анимации не идёт; при `prefers-reduced-motion` показывается статичный выбранный кандидат. Обратный переход в сферу сохранён.
- При наведении мышью на финальную фразу появляется белая SVG-формула с локальным плавным blur; фраза становится чёрной. На сенсорном вводе курсор не подменяется. SVG входит в автономную сборку.
- Исходные шесть слоёв blur сохранены. Прогон с тремя слоями не показал достаточного выигрыша, чтобы менять характер размытия.

## Публикация и кэширование

Сборка использует esbuild с удалением неиспользуемого кода, разделением модулей и хэшами в именах ресурсов. В неё входят только два используемых WOFF2-шрифта. Для HTML, JS и CSS создаются `.br` и `.gz`.

`serve.mjs` проверяет поддержку сжатия клиентом, выставляет MIME-типы и заголовки:

- HTML: `Cache-Control: no-cache`.
- Хэшированные ресурсы: `Cache-Control: public, max-age=31536000, immutable`.
- Сжатые ответы: `Content-Encoding` и `Vary: Accept-Encoding`.

Файл `dist/_headers` задаёт кэширование для совместимых статических хостингов при публикации в корень сайта. На другом хостинге нужно включить аналогичные заголовки и Brotli/gzip средствами сервера; простого наличия `.br` недостаточно. При размещении под URL-префиксом скорректируйте пути правил хостинга. Локальный preview слушает только 127.0.0.1.

Размер всех файлов сборки с Brotli и двумя шрифтами — около 295 КБ; карта стран загружается после первого кадра сферы. Фактический сетевой объём зависит от кэша и поддержки сжатия хостингом.

## Проверки и замеры

```sh
npm test
# Сравнения с предыдущей версией, только внутри исходного репозитория:
npm run bench
node benchmarks/verify-backup.mjs
```

Сначала выполните сборку, чтобы тесты сжатия и HTTP-заголовков также запускались. Проверено на Node 24.11.1. Тесты сравнивают с версией 02 точную раскладку, анимацию логотипа и эллипсы рендера; проверяют 4 px / 6 px, обратимость перехода, выбор стран, очередь worker, кэш, резервный путь, Search и доставку сборки.

Сам сайт, сборка и основные тесты автономны. Если оставить только папку `03`, три исторических сравнения с `02`/`src` автоматически пропускаются. `npm run bench`, проверка бэкапа и сравнение `02` в браузерном стенде требуют исходного генератора и/или папки `02`; это вспомогательные инструменты, сайт их не загружает. Удаление остальных папок для работы сайта не требуется.

Интерактивный стенд: <http://127.0.0.1:8001/website/03/benchmarks/browser.html>. Прогон: 5 секунд вниз, 3 секунды движения курсора по сетке, 5 секунд обратно. Стенд читает версию 02 без изменения её файлов. Вариант blur с тремя слоями включается только в стенде.

Результаты — `benchmarks/browser-results.json` и `benchmarks/node-results.json`. Это локальный WebKit с тёплым HTTP-кэшем без ограничения CPU/сети. Мобильный размер проверен на этом компьютере; это не измерение на физическом телефоне. Результаты отдельных прогонов могут колебаться.

| Показатель | 02 | 03 |
| --- | ---: | ---: |
| Десктоп, обработка кадров p95 | 20.2 мс | 9.3 мс |
| Мобильный размер, обработка кадров p95 | 7.7 мс | 3.3 мс |
| Десктоп, DOMContentLoaded | 453 мс | 44.8 мс |
| Мобильный размер, DOMContentLoaded | 291.3 мс | 54.4 мс |

Появление сферы в мобильном размере не ускорилось; выигрыш состоит в ранней готовности интерфейса и меньшем времени обработки кадров. DOMContentLoaded и первая команда отрисовки canvas не являются измерением LCP.
