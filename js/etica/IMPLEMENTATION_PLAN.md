# Etica: План реализации веб-рисовалки с живыми растровыми линиями

## 1. Как я понимаю задачу

Etica в V1 — это веб-рисовалка для ручного черно-белого дудлинга, где линия выглядит не как чистый векторный stroke, а как живая растровая масса: точки, комки, зернистые края, случайные отпечатки и слипания. Визуально нужно уметь получать оба полюса из референсов:

- разрозненная точечная линия, где рисунок собирается из отдельных черных отпечатков;
- более плотная кляксоподобная линия, где отпечатки частично слипаются в чернильные формы.

Boopy важен не как кодовая база для копирования, а как источник ощущения. В нем нет сложной физики: главная магия в том, что рисование происходит в растровый canvas с рандомизированными отпечатками, а динамика сделана через кольцо bitmap-кадров. Для Etica V1 приоритет — статичный PNG, но архитектуру стоит сразу сделать так, чтобы V2 могла добавить анимацию.

Термин для анимации, которую ты описал: **line boil** или **boiling line animation**. По-русски часто говорят "кипение линии". Это когда один и тот же рисунок перерисован несколько раз с небольшими отличиями, а при проигрывании секвенции появляется приятная дрожащая ручная линия. Для Etica это более подходящий будущий путь, чем boopy-подход с непрерывно обновляемым кольцом кадров.

## 2. Зафиксированный V1 scope

V1 должна уметь:

- работать как веб-приложение в браузере;
- открываться сразу в рабочем интерфейсе рисования, без лендинга;
- создавать canvas по умолчанию 1080 x 1080 px;
- позволять менять размер canvas: по умолчанию квадрат 1080 x 1080, плюс presets стандартных пропорций и ручной ввод;
- рисовать черным по белому;
- иметь два режима кисти:
  - dotted / particle: линия из отдельных точек и отпечатков;
  - ink / blob: более плотная линия со слипанием пятен;
- настраивать размер кисти;
- настраивать плотность точек постфактум, с перерисовкой уже сделанных мазков;
- поддерживать eraser;
- поддерживать undo;
- поддерживать clear;
- экспортировать PNG;
- работать мышью, тачем и стилусом через Pointer Events.

Не входит в V1:

- цвет;
- GIF/video export;
- генерация по prompt;
- автоматическая стилизация загруженной картинки;
- многослойность;
- полноценная галерея или сохранение проектов.

## 3. Решение по Apple Pencil / pressure

Поддержку pressure стоит заложить в V1, но сделать ее прагматично:

- использовать `PointerEvent.pressure`, если браузер/устройство его дает;
- если pressure недоступен или равен `0`, подставлять нормализованное значение по умолчанию;
- добавить переключатель/настройку "Pressure affects size" можно не в первый экран, но движок кисти должен это поддерживать сразу;
- не строить V1 вокруг pressure как обязательной функции, потому что поведение отличается между Safari, iPadOS, macOS, трекпадом и мышью.

Итого: **делать поддержку pressure в V1 на уровне brush engine, но не превращать ее в рискованный центральный feature**.

## 4. Продуктовая модель интерфейса

Первый экран — рабочая рисовалка:

- центр: белый canvas с реальным размером 1080 x 1080 по умолчанию;
- вокруг canvas — спокойная рабочая область, без декоративных hero-блоков;
- верхняя или боковая панель инструментов:
  - brush mode: dotted / ink / eraser;
  - brush size;
  - density, с перерисовкой уже сделанных strokes;
  - canvas size;
  - undo;
  - clear;
  - export PNG.

Визуальная эстетика UI должна быть утилитарной и не конкурировать с рисунком: белый холст, черная линия, нейтральные controls.

## 5. Рекомендуемый технический стек

Для первого рабочего прототипа используем **plain HTML/CSS/JavaScript + Canvas 2D**, без сборщика.

Причины:

- задача в первую очередь про canvas engine, а не сложное состояние интерфейса;
- приложение можно запускать обычным статическим сервером;
- меньше абстракций между pointer-событиями и рисованием;
- проще контролировать производительность и экспорт;
- V2 можно расширить без миграции.

Если позже появятся панели, пресеты, история документов, референсы и prompt-workflows, можно перейти на React/TypeScript или добавить небольшой state layer.

## 7. Canvas architecture

Использовать два canvas-слоя:

- visible canvas: то, что видит пользователь;
- working/offscreen canvas: для отдельных операций кисти, eraser и будущего экспорта/анимации.

Для V1 можно рисовать напрямую в visible canvas, но полезно сразу держать controller, который знает:

- logical canvas size, например 1080 x 1080;
- CSS display scale;
- devicePixelRatio;
- mapping pointer coordinates -> canvas coordinates;
- current brush;
- history stack.

Важно: canvas должен экспортироваться в реальном размере, не в CSS-размере. Если пользователь выставил 1080 x 1080, PNG должен быть 1080 x 1080.

## 8. Brush engine

Общий интерфейс кисти:

```ts
type BrushPoint = {
  x: number;
  y: number;
  pressure: number;
  time: number;
  pointerType: "mouse" | "pen" | "touch";
};

type BrushSettings = {
  size: number;
  density: number;
  jitter: number;
  opacity: number;
};

interface Brush {
  begin(point: BrushPoint): void;
  move(from: BrushPoint, to: BrushPoint): void;
  end(point: BrushPoint): void;
}
```

### DottedBrush

Цель: портрет/цветок из референсов, где форма собирается из отдельных отпечатков.

Поведение:

- по пути pointer-движения расставлять отпечатки с интервалом, зависящим от размера кисти;
- каждый отпечаток получает random offset, random radius, random opacity/noise;
- spacing не должен быть идеально равномерным;
- при медленном движении плотность выше, при быстром — больше разрывов;
- pressure может влиять на radius и density.

Параметры:

- size;
- density;
- jitter;
- dot roundness/noise;
- optional "scatter".

### InkBrush

Цель: третий референс, где точки превращаются в плотные чернильные острова.

Вариант реализации V1:

- использовать те же stamp-отпечатки, но ставить их чаще и крупнее;
- добавлять overlap;
- использовать мягкий noisy edge;
- рисовать не идеальные круги, а blob-stamps из нескольких микрокругов вокруг центра.

Более продвинутый вариант:

- рисовать в offscreen mask;
- применять blur;
- затем threshold/contrast, чтобы получить metaball-like слипание.

Для V1 лучше начать с stamp-based blob brush, потому что она проще, быстрее и контролируемее. Blur-threshold оставить как экспериментальный режим, если базовая кисть не даст нужного ощущения.

### EraserBrush

Eraser должен работать как кисть, но с `globalCompositeOperation = "destination-out"` или рисованием белым, в зависимости от того, хотим ли поддерживать прозрачность.

Для V1, так как экспорт черное на белом, проще:

- canvas background always white;
- eraser рисует белыми stamp-отпечатками;
- при export PNG сохраняется белый фон.

## 9. Фактура отпечатка

Чтобы линия не выглядела векторной, нельзя использовать только `ctx.arc()` с гладким fill. Нужен stamp:

- маленький offscreen canvas с процедурным пятном;
- край пятна слегка неровный;
- внутри пятна может быть grain/noise;
- несколько вариантов stamp кешируются при старте;
- каждая точка выбирает случайный stamp, поворот и размер.

Простой алгоритм stamp:

- создать offscreen canvas 64 x 64 или 128 x 128;
- построить пятно из 8-20 перекрывающихся кругов вокруг центра;
- добавить alpha noise по краям;
- сохранить как bitmap;
- при рисовании масштабировать под текущий size.

Это даст "живую печать", а не стерильную геометрию.

## 10. Undo / History / Stroke log

Для Etica лучше сразу использовать stroke log как главный источник правды:

- каждый stroke хранит tool, brush mode, settings, seed и массив pointer-точек;
- undo удаляет последний stroke и перерисовывает canvas;
- изменение density постфактум перерисовывает все strokes с новым множителем плотности;
- resize с сохранением без масштабирования сдвигает координаты всех strokes на разницу центров;
- eraser тоже хранится как stroke и перерисовывается вместе с остальными.

Bitmap history проще, но хуже подходит под постфактум-density и будущий line boil. Поэтому V1 сразу идет через stroke log, а raster canvas считается результатом рендера.

## 11. Canvas size control

По умолчанию:

- 1080 x 1080 px.

V1 controls:

- width input;
- height input;
- aspect presets: 1:1, 16:9, 9:16, 5:4, 4:5, 4:3, 3:4, 2:3, 3:2, 9:26, 26:9;
- size presets built from the selected ratio, with 1080 as the default short/primary side;
- apply resize.

При изменении размера:

- рисунок сохраняется без масштабирования;
- все strokes сдвигаются так, чтобы старый центр рисунка оказался в новом центре;
- если новый canvas меньше, лишнее визуально кропается;
- если новый canvas больше, вокруг добавляются поля.

## 12. Export PNG

Экспорт:

- временно собрать белый фон + drawing в export canvas;
- вызвать `toBlob("image/png")`;
- скачать файл, например `etica-doodle.png`;
- сохранить реальный pixel size canvas.

Важно: если eraser реализован через прозрачность, экспортный canvas должен сначала заливаться белым.

## 13. Будущая анимация: line boil

Для V2 можно добавить режим animated export:

- хранить stroke history не только как bitmap, а как список stroke points + brush settings + random seed;
- для каждого animation frame перерисовывать тот же рисунок с другим seed или controlled jitter;
- экспортировать GIF/WebM/APNG;
- дать настройки:
  - frame count: 2-8;
  - boil amount;
  - FPS;
  - hold frames.

Ключ: V2 line boil лучше строить не как Boopy, где canvas постоянно живет в кольце кадров, а как **детерминированное перерисовывание одного рисунка несколько раз**. Поэтому уже в V1 полезно думать о stroke model, даже если undo пока bitmap.

Компромисс:

- V1 хранит bitmap history для undo;
- параллельно можно хранить lightweight stroke log для будущего replay.

## 14. Будущее: рисование по загруженной картинке-референсу

Идеальный инструмент может иметь reference layer:

- пользователь загружает картинку;
- она показывается полупрозрачным слоем под canvas;
- можно менять opacity, scale, position;
- export PNG не включает reference, если пользователь явно не выбрал иначе.

Дальше можно добавить guided mode:

- edge detection / contour map;
- posterization / threshold preview;
- подсказки плотности точек по темным зонам;
- режим "trace assist", где кисть чуть притягивает точки к краям или тонам референса.

Это не должно превращать инструмент в фильтр. Лучший вариант — оставить автору ручное рисование, а reference использовать как мягкую подложку и подсказку.

## 15. Будущее: prompt-to-doodle

Prompt workflow можно реализовать несколькими уровнями:

### Уровень 1: prompt как композиционный референс

- пользователь вводит prompt;
- генерируется простая черно-белая reference image;
- она кладется под canvas как подложка;
- пользователь вручную обводит/интерпретирует.

Это самый честный и контролируемый путь для инструмента рисования.

### Уровень 2: prompt -> stroke guide

- prompt генерирует silhouette/line-art;
- приложение превращает контуры в guide paths;
- пользователь рисует поверх точечной кистью;
- можно включить слабый magnet/snap к guide.

### Уровень 3: prompt -> auto doodle

- prompt генерирует композицию;
- алгоритм сам раскладывает точки/кляксы по тонам и контурам;
- результат можно дорисовывать руками.

Для Etica лучше начинать с уровня 1 или 2, потому что они сохраняют характер инструмента: человек рисует, а не просто применяет эффект.

## 16. Implementation phases

### Phase 0: Project setup

- создать статический HTML/CSS/JS проект;
- настроить простой локальный сервер;
- добавить базовый layout;

### Phase 2: Input system

### Phase 3: DottedBrush

## 17. Acceptance criteria for V1

V1 можно считать готовой, если:

- пользователь может открыть страницу и сразу рисовать;
- по умолчанию canvas 1080 x 1080;
- dotted brush дает читаемую россыпь точек;
- ink brush дает плотные слипшиеся пятна;
- eraser удаляет в той же эстетике;
- undo возвращает предыдущий stroke;
- clear очищает canvas;
- canvas size можно изменить;
- PNG экспортируется в правильном размере;
- мышь, touch и stylus работают через одну pointer-систему;
- отсутствие pressure не ломает рисование;
- интерфейс не перекрывает холст и не выглядит как демо-лендинг.

## 18. Открытые вопросы

Решенные вопросы после уточнения:

1. Canvas по умолчанию квадратный 1080 x 1080, но V1 поддерживает любые width/height и стандартные пропорции.
2. Resize сохраняет рисунок без масштабирования: центр остается центром, лишнее кропается или появляются поля.
3. Eraser фактурный, в той же эстетике, что и кисть.
4. Density нужен в V1 и должен уметь менять плотность уже нарисованных strokes.
5. Stroke log стоит хранить сразу, потому что это нужно для density, undo, будущей анимации, reference workflows и возможной генерации strokes.

Решено в текущем прототипе: добавлен toggle `Transparency`, который экспортирует только нарисованные линии на прозрачном фоне, без canvas/background image.

## 19. Рекомендации по первым решениям

- Canvas: любые width/height, но с быстрыми presets пропорций.
- Resize: preserve without scale, с центрированием старого рисунка в новом canvas.
- Background: экспорт всегда белый, UI может быть нейтрально-серым вокруг.
- Eraser: фактурный белый stamp, чтобы стирание не выглядело чужеродно.
- Controls V1: size и density обязательны.
- Stroke log: хранить уже в V1 и использовать для undo, resize, density redraw и будущей line boil-анимации.

Создан plain HTML/CSS/JS прототип:

- `css/styles.css`, который подключает `yf-styles-no-fonts.css` и содержит только Etica-specific layout overrides;
- `js/main.js`;
- `js/canvas/CanvasController.js`;
- `js/canvas/Exporter.js`;
- `js/brushes/BrushEngine.js`;
- `js/brushes/stamps.js`;
- `js/brushes/random.js`;
- `js/input/PointerTracker.js`;
- `js/ui/Toolbar.js`.

UI переведен на YF UI Framework v2:

- верхняя кнопка `YF Tools` заменена на кнопку `Etica` без ссылки;
- настройки используют `controls-panel`, `control-section`, `segmented-control`, `value-display`, `style-select` и framework-кнопки;
- canvas размещен внутри `canvas-container`;
- действия вынесены в `bottom-buttons`.
- `Settings` panel подключена к `PanelManager` из YF v2 и перетаскивается за header.

Добавленные решения после уточнений:

- canvas по умолчанию черный, с тонкой темно-серой границей;
- strokes рендерятся белой растровой фактурой на отдельном прозрачном stroke layer;
- eraser работает через `destination-out`, то есть стирает strokes и не закрашивает загруженный фон;
- можно загрузить background image, она рисуется contain-fit под strokes;
- добавлен `Select` tool для выбора линии по hit-test к polyline;
- выбранная линия подсвечивается серым dashed overlay;
- в режиме `Select` hover над линией рендерит ее с opacity 70%;
- sliders `Size` и `Density` редактируют выбранную линию постфактум;
- если линия не выбрана, `Size` и `Density` задают настройки будущих strokes;
- добавлен redo stack и `Redo` action, включая `Cmd/Ctrl + Shift + Z`.
- `Export ⌘E` экспортирует обычный PNG, а toggle `Transparency` экспортирует только нарисованные линии на прозрачном фоне;
- hotkeys: `V` Select, `B` Dots, `I` Ink, `E` Erase, `Cmd/Ctrl + E` Export.

Сервер запущен из lowercase-папки проекта на `http://127.0.0.1:8080/` в detached `screen` session с именем `etica-server`. Такой процесс продолжит работать после закрытия редактора/текущего окна Codex. Остановить его можно командой:

```sh
screen -S etica-server -X quit
```
